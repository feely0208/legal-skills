# 答辩状技能

以中国执业律师视角，根据对方提交的起诉状/上诉状/申请书等法律文书，结合当事人陈述和证据材料，撰写规范的民事/行政答辩状，最终在桌面生成以案件名命名的文件夹，内含 Word 答辩状、PDF 文件、Markdown 报告和交互式思维导图。

## 完整工作流程

### 第零步：收集案件信息

在开始撰写答辩状前，向用户确认以下信息（信息充分时直接开始）：

#### 必须确认

| 信息项 | 说明 |
|--------|------|
| 答辩人立场 | 答辩人是原告还是被告（用于准确确定文书格式和答辩策略） |
| 案件信息 | 案号、审理法院、当事人名称（原告、被告全称） |
| 对方文书 | 对方提交的起诉状/上诉状/申请书等文件（需逐一读取） |
| 答辩人信息 | 姓名/名称、性别、出生日期、民族、职业、住址、联系方式（自然人）或公司全称、法定代表人、统一社会信用代码、地址（法人） |

#### 自动判断原告/被告

若用户未明确说明立场，从以下线索自动推断：

- **对方提交起诉状/民事起诉状** → 答辩人是**被告**（最常见情形）
- **对方提交上诉状** → 答辩人是**被上诉人**
- **对方提交再审申请书** → 答辩人是**被申请人**
- **对方提交反诉状** → 答辩人是**本诉原告**（即反诉被告）
- **用户表述** → "对方起诉了我"、"我被人告了"、"收到法院传票"等措辞
- **文件名** → 从"民事起诉状——XXX"、"上诉状"等文件名判断对方立场

#### 答辩策略差异

| 维度 | 被告答辩（最常见） | 原告答辩（反诉/上诉场景） |
|------|---------------------|--------------------------|
| 核心目标 | 反驳原告诉讼请求，促请法院驳回起诉 | 反驳被告反诉/上诉人上诉，维持己方有利判决 |
| 答辩策略 | 逐一驳斥原告诉讼请求和事实理由 | 维护一审判决/己方立场 |
| 举证责任 | 原告承担举证责任，答辩人可只需反驳 | 视具体诉讼地位而定 |
| 常用策略 | 否认事实、指出证据瑕疵、引用时效抗辩 | 强调一审正确、对方无新证据/新理由 |
| 法律依据 | 《民事诉讼法》第125条（答辩权）等 | 同上，视诉讼程序而定 |

#### 选填信息

| 信息项 | 说明 |
|--------|------|
| 代理人信息 | 代理人姓名、律师事务所、执业证号、联系方式 |
| 答辩人补充陈述 | 答辩人就案件事实的补充说明和辩解 |
| 补充证据 | 答辩人拟提交的反驳证据材料 |
| 特殊说明 | 管辖权异议、诉讼时效抗辩、反诉意向等 |

### 第一步：读取对方文书

用 `scripts/read_evidence.py` 逐份读取对方提交的法律文书和证据文件：

```bash
python "<skill目录>/scripts/read_evidence.py" "对方文书路径" --output "/tmp/defense_input_N.txt"
```

支持以下格式：

| 格式 | 扩展名 | 读取方式 |
|------|--------|---------|
| PDF | .pdf | pdfplumber / PyPDF2 |
| Word | .docx | python-docx |
| 旧版Word | .doc | olefile |
| 图片 | .jpg/.jpeg/.png/.bmp | AI视觉识别（通过Read工具直接读取） |
| CSV | .csv | 内置 |
| 纯文本 | .txt | 内置（自动检测编码） |
| JSON | .json | 内置 |
| HTML | .html/.htm | beautifulsoup4 |

**图片文件处理**：对于图片格式的文件（.jpg/.jpeg/.png/.bmp），脚本会返回 `[IMAGE]` 标记及文件路径，此时应使用 **Read 工具**直接读取图片文件，Claude 将自动识别图片中的文字内容和图像信息。

如果文本超过 50000 字符，用 `--max-chars` 参数调整上限。

全部文书读取完成后，开始撰写答辩状。

### 第二步：梳理原告诉讼请求与事实理由

**务必同时阅读 `references/defense_statement_guide.md` 获取答辩状格式规范、法律依据汇编和各类案件的答辩要点。**

细致梳理对方文书中的以下内容：

#### 2.1 诉讼请求拆解

逐项拆解对方的诉讼请求（诉请），形成清单：

```
诉请1：判令被告支付货款人民币XX元
诉请2：判令被告支付逾期付款违约金人民币XX元
诉请3：判令被告承担本案诉讼费用
```

#### 2.2 事实与理由提取

从对方文书中提取其主张的核心事实：

| 对方主张的事实 | 事实要点 | 证据支撑 |
|---------------|---------|---------|
| 事实1 | 双方于XX年XX月XX日签订XX合同 | 对方提交证据1 |
| 事实2 | 原告已按约定交付货物 | 对方提交证据2 |
| ... | ... | ... |

#### 2.3 法律依据分析

分析对方引用的法律依据，预判其法律论证的逻辑链条，寻找可能的漏洞：
- 法条是否适用本案情形
- 是否存在法条适用的例外情形
- 是否有更高效力层级的法律规范与之冲突

### 第三步：逐项撰写答辩意见

对每一项诉讼请求，撰写针对性的答辩意见：

#### 3.1 答辩请求结构

对每一项原告诉讼请求，明确答辩态度：

| 态度类型 | 表述范例 | 适用场景 |
|---------|---------|---------|
| **完全驳回** | "答辩人请求人民法院依法驳回原告该项诉讼请求" | 原告该项诉请无事实和法律依据 |
| **部分认可** | "答辩人对原告该项诉请中的XX部分予以认可，对其余部分不予认可" | 诉请中部分合理，部分不合理 |
| **认可但需澄清** | "答辩人对该项诉请的事实基础予以认可，但认为原告主张的金额/范围有误" | 认可基本事实但不同意具体诉求 |

#### 3.2 事实与理由撰写框架

答辩状的「事实与理由」部分按以下结构组织：

```
一、对原告所述事实的回应（逐项）

1. 关于原告主张的「XX事实」：
   答辩人认为该主张【属实/不属实/部分属实】。
   事实真相是：……（详述答辩人版本的事实）
   依据：……（如有证据）

2. 关于原告主张的「YY事实」：
   ……

二、本案基本事实（答辩人版本）

答辩人认为，本案的基本事实如下：
1. ……
2. ……
3. ……
（按时间顺序完整陈述答辩人认可的案件事实经过）

三、法律适用意见

1. 原告引用《XX法》第X条不适用于本案，理由如下：……
2. 根据《XX法》第Y条，答辩人认为：……
3. 相关司法解释/指导案例：……

四、对原告证据体系的整体评价

（如有必要）指出原告证据链的断裂、矛盾或不足
```

#### 3.3 常见答辩理由

| 类型 | 答辩理由 | 法律依据 |
|------|---------|---------|
| **事实否认** | 原告主张的事实根本不存在或与事实不符 | 《民诉法解释》第90条（谁主张谁举证） |
| **法律适用抗辩** | 原告引用的法律规定不适用于本案 | 相关实体法条文 |
| **时效抗辩** | 原告诉讼请求已超过诉讼时效 | 《民法典》第188-197条 |
| **履行抗辩** | 答辩人已履行完毕合同义务 | 《民法典》第509、557条 |
| **同时履行抗辩** | 原告未履行其义务，答辩人有权拒绝履行 | 《民法典》第525条 |
| **先履行抗辩** | 原告应先履行而未履行 | 《民法典》第526条 |
| **不安抗辩** | 原告经营状况严重恶化等 | 《民法典》第527-528条 |
| **抵销抗辩** | 答辩人对原告享有到期债权，主张抵销 | 《民法典》第568-569条 |
| **免责抗辩** | 不可抗力、情势变更或原告过错导致 | 《民法典》第180、590、533条 |
| **违约金过高** | 原告主张的违约金过分高于实际损失 | 《民法典》第585条 |
| **格式条款无效** | 原告依据的条款系无效格式条款 | 《民法典》第496-498条 |
| **合同无效抗辩** | 涉案合同存在法定无效情形 | 《民法典》第144、146、153、154条 |

### 第四步：质量检查

#### 4.1 格式规范性检查

- [ ] 标题正确（"民事答辩状"或"行政答辩状"）
- [ ] 答辩人信息完整（自然人或法人所需字段齐全）
- [ ] 被答辩人信息完整
- [ ] 案号、案由正确
- [ ] 答辩请求明确、逐项对应原告诉讼请求
- [ ] 事实与理由逻辑清晰、层次分明
- [ ] 法条引用准确
- [ ] 结尾格式正确（此致 + 法院名称）
- [ ] 签名栏和日期栏齐全

#### 4.2 法律逻辑检查

- [ ] 答辩请求与事实理由之间逻辑自洽
- [ ] 对每一项原告诉讼请求均有明确答辩意见
- [ ] 法条引用现行有效、编号准确
- [ ] 不存在自认对己方不利的事实（除非有策略考量）
- [ ] 时效抗辩、管辖权异议等程序性抗辩如适用需在答辩状中提出

#### 4.3 语言表达检查

- [ ] 用语规范、语气理性平和
- [ ] 不得使用侮辱性、攻击性语言
- [ ] 事实陈述清晰、时间线完整
- [ ] "答辩人""被答辩人"指代一致

**JSON 注意事项**：
- 所有中文双引号必须用 `「」` 或 `『』` 代替 `""`
- `respondent_role`: `"defendant"` = 被告答辩（最常见），`"plaintiff"` = 原告答辩（反诉/上诉场景）
- `respondent.type` 和 `counterparty.type`: `"individual"` = 自然人，`"company"` = 法人/组织
- 自然人需填写 `gender`、`birth_date`、`ethnicity`、`occupation`，法人的这些字段留空
- 法人需填写 `legal_rep`（法定代表人）、`credit_code`（统一社会信用代码），自然人的这些字段留空
- `defense_position`: `"驳回"` / `"部分认可"` / `"认可但需澄清"` / `"认可"`
- `claims_response` 数组必须与原告起诉状中的诉讼请求项一一对应
- `response_to_plaintiff_facts` 中的 `respondent_position`: `"属实"` / `"不属实"` / `"部分属实"`

#### 5.2 确定输出文件夹

从案件名称提取文件夹名，在桌面创建：

```
~/Desktop/<案件名称>答辩状/
```

例如案号为"（2026）粤0106民初1234号"的案件，文件夹名可为"XX诉YY案答辩状"。

#### 5.3 运行生成脚本（顺序运行）

```bash
# 1. 生成 Word 答辩状
python "<skill目录>/scripts/generate_defense_docx.py" \
  --input "/tmp/defense_statement.json" \
  --output "~/Desktop/<案件名称>答辩状/<案件名称>-答辩状.docx"

# 2. 生成 Markdown 答辩状
python "<skill目录>/scripts/generate_defense_md.py" \
  --input "/tmp/defense_statement.json" \
  --output "~/Desktop/<案件名称>答辩状/<案件名称>-答辩状.md"

# 3. 生成思维导图（.html + .mm）
python "<skill目录>/scripts/generate_mindmap.py" \
  --input "/tmp/defense_statement.json" \
  --output-dir "~/Desktop/<案件名称>答辩状/"

# 4. 将 DOCX 转换为 PDF
python "<skill目录>/scripts/convert_to_pdf.py" \
```

## 答辩原则

### 必须做到

1. **逐项回应诉讼请求**：对原告每一项诉讼请求必须明确答辩态度，不得遗漏
2. **事实陈述清晰**：答辩人版本的事实必须完整、清晰、时间线明确
3. **法条引用准确**：只引用现行有效法律法规，不确定时以"根据相关法律规定"代替，绝不编造
4. **程序权利提示**：如存在管辖权异议、诉讼时效抗辩等，必须在答辩状中提出
5. **逻辑自洽**：答辩理由之间不得相互矛盾，不得出现"既认定义否认同一事实"的情况
6. **语气理性平和**：使用规范法律语言，避免情绪化表达
7. **逐项核实信息**：当事人信息、案号、法院名称等必须准确无误
8. **证据呼应**：答辩状中的事实主张应与拟提交的证据材料相互印证
9. **立场一致**：全文保持一致的答辩人视角
10. **格式规范**：符合中国法院法律文书排版习惯

### 禁止事项

- 不得编造不存在的法条编号或案号
- 不得对原告诉讼请求不予回应或遗漏
- 不得使用侮辱性、攻击性语言攻击对方或对方代理人
- 不得在答辩状中自认对己方明显不利且不必要的事实
- 不得虚构证据或伪造事实
- 不得在答辩状中直接提起反诉（反诉应另行提交反诉状）
- 不得将答辩状写成"诉苦书"或"批斗信"——应有理有据、依法论述
