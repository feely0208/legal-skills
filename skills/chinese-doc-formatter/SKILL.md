# 中文文书排版技能

生成排版规范的中文常规文书（通知、报告、函、文件等）。输出 .docx / .pdf / .txt 三种文件，全文统一使用仿宋（GB2312 简体字集）排版，严格遵循以下规范，且文档内不出现任何 AI 生成痕迹（无水印、无生成标记、无作者信息、无版本说明）。

## 字体字号规范

### 正文内容

| 元素 | 字体 | 字号 | 字号对照（磅） |
|------|------|------|---------------|
| 标题 | 仿宋（全文统一） | 二号加粗 | 22pt |
| 正文 | 仿宋 | 四号 | 14pt |
| 一级标题 | 仿宋 | 三号加粗 | 16pt |
| 二级标题 | 仿宋 | 三号加粗 | 16pt |
| 三级标题 | 仿宋 | 三号加粗 | 16pt |
| 四级标题 | 仿宋 | 三号加粗 | 16pt |
| 数字/英文 | 仿宋（与全文一致） | 四号 | 14pt |
| 页码 | 仿宋阿拉伯数字 | 四号半角 | 14pt |

### 版头（可选，仅红头文件需要，常规文书默认不输出）

份号顶格居左第一行、密级第二行、紧急程度第三行（仿宋三号）；发文字号仿宋三号（上行文左空一字，否则居中）。不设签发人。

### 附件、落款、日期

| 元素 | 字体 | 字号 |
|------|------|------|
| 附件说明 | 仿宋 GB2312 | 四号 |
| 发文机关署名 | 仿宋 GB2312 | 四号 |
| 成文日期 | 仿宋 GB2312 | 四号 |

## 行距与页边距规范

| 项目 | 规范值 |
|------|--------|
| 标题行距 | 固定值 33-36 磅 |
| 正文行距 | 固定值 28 磅 |
| 上边距 | 3.7 cm |
| 下边距 | 3.5 cm |
| 左边距 | 2.8 cm |
| 右边距 | 2.6 cm |
| 文档网格 | 每面排 22 行，每行排 28 个字（Word 按 28 磅行距设置 docGrid） |

## 输出文件规范

生成文件须同时输出以下格式：
1. **Word 文档 (.docx)** — 标准排版，可编辑
2. **PDF 文件 (.pdf)** — 打印级质量，与 Word 排版一致
3. **纯文本文件 (.txt)** — 无格式，保留标题层级结构

所有文件保存在用户指定的输出目录（默认为桌面 `公文排版输出/` 目录）。

## 无 AI 痕迹要求

生成的文档必须是纯粹、专业的公文，不得包含：
- 任何作者署名、AI 标记、生成时间戳
- 任何解释性文字、注释或说明
- 任何文档结构说明或元信息
- 任何来源标注或版权信息

文档应仅包含用户要求的内容本身，格式专业、干净。

## 字体回退策略

由于 macOS 系统可能没有 Windows 专有的字体（如仿宋 GB2312、方正小标宋简体），按以下回退顺序处理：

### Word 文档 (.docx) — 全文统一仿宋
脚本按以下优先级**实测本机已装字体**后选定，取第一个命中的：

| 顺序 | 字体族名 | 说明 |
|---|---|---|
| 1 | `仿宋_GB2312` | Windows 标准公文仿宋 |
| 2 | `FangS-SC` | **本 skill 随附**（`fonts/FangS-SC.ttf`），首选 |
| 3 | `FandolFang R` | macOS 常见仿宋替代 |
| 4 | `STFangsong` | macOS 华文仿宋 |
| 5 | `Songti SC` | 最后回退：宋体 |

标题与小标题通过加粗区分：

| 元素 | 字体 | 加粗 |
|------|------|------|
| 标题 | 仿宋_GB2312（未安装时 FandolFang） | 是 |
| 正文 | 仿宋_GB2312（未安装时 FandolFang） | 否 |
| 一/二/三/四级标题 | 仿宋_GB2312（未安装时 FandolFang） | 是 |
| 附件、署名、日期、页码 | 仿宋_GB2312（未安装时 FandolFang） | 否 |

#### 字体获取（**本仓库不含常规仿宋**）

本仓库仅包含 `fonts/FangS-SC-Bold.ttf`（仿宋粗体）。
**常规仿宋 `FangS-SC.ttf` 因字体厂商授权原因未随仓库分发**，请自行获取，
任选其一放置即可（脚本按此顺序查找）：

1. 放入本 skill 的 `fonts/FangS-SC.ttf`
2. 复制到 `~/Library/Fonts/FangS-SC.ttf`
3. 安装 WPS Office（安装目录内自带该字体）

未提供时：
- **docx** 会依次回退到本机已装的 `FandolFang R` → `STFangsong` → `Songti SC`
- **pdf** 会退回宋体，并在 stderr 打印获取提示

若排版必须严格符合 GB2312 仿宋规范，请确保上述任一路径可用。

### PDF 文档 — 使用系统 TrueType 字体
PDF 生成时直接绑定字体，全文统一仿宋：

- 正文/附件/署名/日期/页码 → WPS `FangS-SC.ttf`（仿宋，TrueType）
- 标题与小标题 → skill 自带 `fonts/FangS-SC-Bold.ttf`（由 FangS-SC 生成的仿宋粗体）
- 找不到上述字体时回退为系统宋体（`Songti.ttc`）

### 页码处理
页码使用宋体，四号（14pt）半角阿拉伯数字，格式为 `- 1 -`：
- PDF：每页页脚输出，单页码居右空一字，双页码居左空一字
- Word：页脚插入 PAGE 域，奇数页居右空一字，偶数页居左空一字

## 工作流程

### 第一步：确认文档类型和内容

向用户确认：
- 文档类型：一般文书（通知、函、报告等）/ 红头文件 / 其他正式文本
- 是否需要版头（份号、密级、紧急程度、发文字号；默认不需要）
- 正文内容是什么
- 输出目录（默认为桌面）

### 第二步：生成文件

调用脚本生成 docx 和 pdf：

```bash
# 生成 Word 文档
python "<skill目录>/scripts/docx_formatter.py" \
  --output /path/to/output \
  --type notice \
  --title "标题文字" \
  --body "正文内容..." \
  --sender "发文机关名称" \
  --date "成文日期"

# 生成 PDF
python "<skill目录>/scripts/pdf_formatter.py" \
  --output /path/to/output \
  --type notice \
  --title "标题文字" \
  --body "正文内容..." \
  --sender "发文机关名称" \
  --date "成文日期"
```

### 第三步：生成 TXT 版本

从内容中提取纯文本，按标题层级保留结构，生成 .txt 文件。

### 第四步：输出自检（**不要跳过**）

```bash
python "<skill目录>/scripts/verify_output.py" --dir <输出目录>
```

逐项核对页边距、标题字号加粗、正文行高、字体是否本机存在、PDF 是否嵌入仿宋、页面是否 A4。
**退出码 0 = 通过，1 = 有不符合项** —— 必须处理完再交付。

### 第五步：确认输出

告知用户文件位置和格式，附上简要说明。

## 从 Markdown 生成（常见场景）

内容常以 Markdown 写就，直接喂给脚本会**丢失层级**（整篇被当正文）。
先用 `md_adapter.py` 转换：

```bash
python "<skill目录>/scripts/md_adapter.py" \
  --input 原文.md --output /tmp/_body.txt [--drop-meta]
```

转换规则：

| Markdown | 转成 | 公文层级 |
|---|---|---|
| `# 标题` | （丢弃，作为 `--title` 传入） | — |
| `## 一、小节` | `一、小节` | 一级标题 |
| `### 1.1 小节` | `（一）小节` | 二级标题 |
| `#### 更深` | `1. 小节` | 三级标题 |
| `- 列表项` | 正文 | 正文 |
| `| 表格 |` | `表头：值；表头：值。` | 正文 |
| `> 引用块` | 正文（连续行自动合并） | 正文 |

再把 `_body.txt` 内容作为 `--body` 传给 docx/pdf 脚本。

**注意**：`md_adapter` 会把同一段内的软换行合并成一行（源文档常手动折行，
逐行当独立段落会在断句处留下孤立标点，如单独一行的「、」）。

## 文档类型说明

| 类型 | 特征 |
|------|------|
| notice（通知） | 最常见，含主送机关、正文、发文机关署名、日期 |
| report（报告） | 上行文，汇报工作、反映情况 |
| letter（函） | 平行文或不相隶属机关之间的商洽工作 |
| decision（决定） | 重要事项决策 |
| opinion（意见） | 对重要问题提出见解和处理办法 |
| other（其他） | 其他正式文本，自定义结构 |

## 特殊处理

### 版头信息
- 份号：顶格居左排在版心第一行
- 密级：第二行；紧急程度：第三行
- 发文字号：仿宋，三号；上行文左空一字，下行文居中
- 不设签发人；常规文书默认不带版头

### 标题格式
- 居中，二号字加粗，仿宋
- 标题行距 33-36 磅

### 一级标题
格式：一、二、三……（仿宋，三号加粗，左空二字）

### 二级标题
格式：（一）（二）（三）……（仿宋，三号加粗，左空二字）

### 三级标题
格式：1. 2. 3. ……（仿宋，三号加粗，左空二字）

### 四级标题
格式：（1）（2）（3）……（仿宋，三号加粗，左空二字）

### 正文段落
- 四号（14pt）仿宋 GB2312，首行缩进严格 2 字

### 发文机关署名和日期
- 距正文（或附件说明）下空 3 行
- 署名以成文日期为准居中编排
- 日期用阿拉伯数字，右空 4 字
- 署名在上，日期在下

### 页码
- 格式："- 1 -"（单页码右空一字，双页码左空一字）
- 位置：版心下边缘之下的页脚区（PDF 每页输出；Word 奇偶页页脚插入 PAGE 域）
- 字体：宋体，四号，半角

## 附录：2026-09-22 修复记录

本 skill 曾有四处缺陷，已在当日修复，此处存档以免重犯。

### 1. 字体探测在 macOS 上恒失败（**最严重**）

```python
# 原实现
out = subprocess.run(['fc-list', f':family={family}'], ...)
return bool(out.stdout.strip())
```

`fc-list` 是 fontconfig 的命令，**macOS 不预装**。异常被 `except` 吞掉后函数恒返回
`False`，于是**即使机器上装了 `仿宋_GB2312` 也检测不到**，永远走回退分支。

→ 已改为直接扫描字体文件读 `name` 表（fontTools），macOS / Windows / Linux 通用，
  并逐个候选名实测，避免再把字体名写错。

### 2. 常规仿宋依赖 WPS 安装路径

`pdf_formatter.py` 只从 `/Applications/wpsoffice.app/...` 找 `FangS-SC.ttf`。
未装 WPS 的机器会**静默退回宋体**，与「全文仿宋」规范不符。

→ 已把 `FangS-SC.ttf` 纳入 `fonts/` 随 skill 分发，查找顺序改为
  本 skill 自带 → 用户字体目录 → WPS → 系统。

### 3. 不支持 Markdown 输入

内容以 Markdown 写就时，整篇会被当作正文，层级全部丢失。

→ 新增 `scripts/md_adapter.py`。

### 4. 没有输出自检

生成完不知道是否真的符合规范（页边距、字号、行距、字体、A4 尺寸）。

→ 新增 `scripts/verify_output.py`，退出码可用于卡口。

### 安装位置说明

skill 实际存放在 `~/.claude/skills/`，同时在 `~/.dsh/skills/` 建了软链接。
**两处都需要**：前者供 Claude Code 使用，后者供 DSH 自动加载。
如新会话未自动加载本 skill，先检查 `~/.dsh/skills/chinese-doc-formatter` 链接是否存在。
