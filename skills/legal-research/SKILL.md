# 法律检索报告技能

## 这个技能解决什么

「这事法律怎么规定的」是最容易被随口回答、也最容易答错的问题。常见三种错：只给一段没有出处的结论；把下位法、会议纪要、甚至一篇公众号文章当成法律依据；拿 2021 年前已废止的《合同法》回答现在的合同问题。

本技能把检索做成可核对的产物：**每个结论都回到法源**，按效力层级排序，逐条标核验状态，把查不到的部分留在明面上。

## 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 一个具体问题需要找法条依据（能不能做、有什么条件、责任怎么承担） | 只要某一条法条的原文或要点 → `legal-statute-lookup` |
| 需要判断新旧法适用、旧法是否已废止 | 已有文书，只需核对引用真假 → `legal-cite-check` |
| 需要类案检索思路与检索式 | 要出具带结论、签章、用途限制的正式意见 → `legal-opinion` |
| 诉讼/非诉方案前的基础调研 | 要逐条审合同 → `legal-contract-review` |
| 跨地域、跨时间的规则差异梳理 | 要算具体金额、写仲裁请求 → `legal-labor-arbitration` |

## 输入

**必需**

1. 检索问题：一句话说清「谁、在什么情况下、想确认什么」。
2. 用途：内部参考 / 给客户 / 支撑起诉状或意见书 —— 决定详略与措辞。
3. 地域：省级即可（地方性法规、赔偿标准、裁判口径差异大）。
4. 时间点：行为发生日、合同成立日或起诉日 —— 决定适用哪一版法。
5. 立场：代理哪一方 / 中立。同一事实，原告与被告的检索方向不同。

**可选**：已知法条、案号、合同条款、已有材料。

缺失时逐项追问，**不要自己补**。尤其是时间和地域：填错一个，整份报告的适用法就错了。

## 工作流程

### 第零步：读法律档案

先读 `~/.deepwhale/深鲸法律档案.md`。不存在时，把仓库里的 `templates/法律档案.md` 复制过去，再逐项问用户：角色（律师/法务/当事人）、立场、执业地域、行文风格、风险偏好、升级链。档案里没填的，不要假设。

检索报告默认按档案里的「常用立场」定方向；本次委托立场与档案不一致时，以本次为准并记下差异。

### 第一步：把口语问题拆成法律问题

不要直接搜原话。先拆成 2–5 个可检索的子问题，并标出哪些是事实、哪些是法律：

| 原始问题 | 拆出的法律问题 | 检索关键词 | 待确认事实 |
|---|---|---|---|
| 「公司能不能直接辞退我」 | 解除类型与法定事由；程序要件；违法解除后果 | 劳动合同法 第39条/第40条/第87条 | 是否签收规章制度、是否有书面通知、解除理由 |
| 「借款利息能要多少」 | 利率上限；新规时间效力；已付利息冲抵 | 民间借贷 利率 LPR 四倍 时间效力 | 合同成立日、放款日、已付利息 |

事实不清的子问题，先列进「待确认事实」，不要用假设往下推。

### 第二步：按效力层级定法源范围

从高到低检索，高阶层级找到就不再往下堆同义条文。完整层级、制定机关、能否作为裁判依据见 `references/source-hierarchy.md`。

要点：

- 法律、行政法规、司法解释是主力；地方性法规只在辖区内有效；
- 部门规章、地方政府规章是「参照」，不能用来否定法律；
- 指导性案例「应当参照」，其他案例只是参考；
- 会议纪要（如九民纪要）**不是法源**，不能作为裁判依据援引，只能在说理时参照；
- 学术文章、公众号、AI 回答一律不作为依据，只能提示线索。

### 第三步：过三道校验（本技能的核心）

| 校验 | 查什么 | 不合格怎么办 |
|---|---|---|
| ① 效力层级 | 有没有用下位法、纪要、普通案例去否定上位法；司法解释是否与法律冲突 | 降为参考，补上位法依据 |
| ② 新旧法时效 | 行为发生时有效的是哪版；现在是否已废止；有无过渡条款 | 改引现行法，并写一句时间效力说明 |
| ③ 引用格式 | 法名全称、条/款/项、司法解释文号、案例四要素 | 按 `references/source-hierarchy.md` 第四节改写 |

第 ② 项最容易漏。凡出现《合同法》《物权法》《担保法》《婚姻法》《继承法》《侵权责任法》《民法总则》，一律改引《民法典》对应条文；条号**不是平移**，必须回原文核对。拿不准就写「对应条文待核」。

### 第四步：类案检索（给路径，不编案号）

本技能离线运行，不自动抓取裁判文书。做法是给出可直接执行的检索式和路径：

```
检索式：（"违约金" AND "过分高于"）AND 案由:买卖合同纠纷
限定：2021-01-01 之后 / 中级以上法院 / 本省
路径：中国裁判文书网、人民法院案例库、指导性案例
```

用户回填真实案号后再写入报告。**没有四要素（案号、法院、裁判日期、裁判要旨）的案例不写**；记不清就标【待核验】。

### 第五步：组织报告

固定七段，结论先行：

1. 结论摘要（3–5 条，每条一句话 + 依据条号）
2. 事实与问题（含「待确认事实」）
3. 法源清单（表：名称 / 条号 / 效力层级 / 核验状态 / 要点）
4. 逐项分析（问题 → 规则 → 涵摄 → 结论）
5. 类案与裁判倾向（没有就写「未检索到可引用案例」）
6. 风险与不确定性（🔴/🟡/⚪）
7. 检索路径、核验说明与复核声明

## 输出规范

- 主文件：`检索报告-<主题>-<YYYYMMDD>.md`，放在本次工作目录。
- 法源清单同时以表格形式写入报告第三节；需要单独交付时另存 `法源清单-<主题>.csv`（列：名称、条号、效力层级、核验状态、要点、来源）。
- 需要正式交付时，用 `chinese-doc-formatter` 转 `.docx` / `.pdf`；转换后仍需人工核对条号。
- 末尾固定两行：

```
依据：见第三节法源清单（条号/文号已逐条标注核验状态）
声明：AI 辅助生成，需承办律师复核；不构成法律意见，不作为对外出具文件。
```

## 质量闸门（交付前自检）

- [ ] 每个法律结论都有依据（法条到条 / 司法解释到文号 / 案例到案号），无源不写
- [ ] 没有编造法条条号、案号、金额、日期；LPR、社平工资等数值一律标【待核验】或留空
- [ ] 已废止旧法全部改引《民法典》等现行法，并注明对应关系是否待核
- [ ] 法源清单有「效力层级」和「核验状态」两列，没有把纪要和普通案例当法律
- [ ] 区分了「可以主张 / 通常 / 需结合…判断」，没有「必然 / 一定 / 保证」
- [ ] 信息缺失处用【待补：xx】占位，没有猜
- [ ] 输出带「AI 辅助生成，需承办律师复核」标识
- [ ] 涉及对外出具、提交法院的动作，已提示人工复核闸门

## 输出示例

```markdown
# 法律检索报告：逾期付款违约金上限

## 一、结论摘要
1. 约定违约金是否过高，以实际损失为基础，兼顾合同履行情况、过错程度等，通常超过损失 30% 可认定「过分高于」。（《民法典》第 585 条；《合同编通则解释》第 65 条，条号待核）
2. 本案合同成立于 2020 年 3 月，违约持续至 2023 年，应适用《民法典》，不适用已废止的《合同法》。
3. 违约金与逾期利息不能重复主张，需择一或说明关系。【待补：合同第 X 条原文】

## 二、事实与问题
- 已知：……
- 待确认：实际损失凭证、对方是否已部分履行、是否约定过调整方式

## 三、法源清单
| 名称 | 条号 | 效力层级 | 核验状态 | 要点 |
|---|---|---|---|---|
| 民法典 | 第585条 | 法律 | 已核（条号） | 违约金调整 |
| 合同编通则解释 | 法释〔2023〕13号 | 司法解释 | 条号待核 | 调整的具体考量 |
| 九民纪要 | 第50条 | 会议纪要（非法源） | 仅参考 | 不能作裁判依据援引 |

## 六、风险与不确定性
- 🔴 合同成立时间未确认，直接影响新旧法适用。
- 🟡 「损失 30%」是常见裁判口径，不是法律硬性上限，需结合类案。
- ⚪ 若对方缺席，法院仍会审查违约金是否过高。

依据：见第三节法源清单
声明：AI 辅助生成，需承办律师复核；不构成法律意见。
```
