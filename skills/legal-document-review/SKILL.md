# 律师阅卷技能

系统化辅助律师完成案卷材料（起诉书、答辩状、证据清单、庭审笔录、合同等）的阅读与分析。

## 核心原则

1. **客观中立** — 区分"事实陈述"与"法律评价"，不替代律师的专业判断
2. **逐份分析** — 每份文件独立标注来源、页码、形成时间
3. **交叉验证** — 将不同文件中相矛盾的事实点高亮标出
4. **引用原文** — 关键表述必须引用原文，不使用概括性转述替代

## 工作流程

### 第一步：确认案卷范围

向用户确认：
- 案卷文件所在的目录或文件列表
- 案件类型（刑事/民事/行政）
- 当前所处阶段（一审/二审/再审/仲裁）
- 用户角色（原告方/被告方/第三人/代理人）
- 需要重点关注的法律关系或争议焦点（如有）

若用户未提供上述信息，基于案卷内容自行初步判断并在报告中标注"待确认"。

### 第二步：逐份阅卷

按以下顺序读取案卷材料：

1. **程序性文书** — 起诉书/答辩状/裁定书/判决书，把握案件全貌
2. **证据材料** — 书证/物证/证人证言/鉴定意见/勘验笔录等
3. **庭审材料** — 庭审笔录/代理词/质证意见
4. **其他材料** — 往来函件/补充材料等

每份文件提取：
- 文件名称、形成时间、来源方
- 核心内容（不超过 5 条关键摘录）
- 与其他文件的关联或矛盾点

### 第三步：生成阅卷报告

报告使用以下结构化模板输出：

---

## 阅卷笔录

### 一、案件概览

| 项目 | 内容 |
|------|------|
| 案由 | |
| 当事人 | 原告/申请人/公诉机关：... / 被告/被申请人/被告人：... |
| 审理阶段 | |
| 阅卷人角色 | |
| 阅卷日期 | |

### 二、基本事实时间线

按时间先后排列案件关键事件，每条标注来源（文件名+页码）：

- YYYY-MM-DD — 事实描述 [来源: xxx.pdf P.3]
- YYYY-MM-DD — 事实描述 [来源: xxx.pdf P.5]

### 三、各方主张与核心观点

**原告方/公诉机关主张：**
1. ...
2. ...

**被告方/被申请人主张：**
1. ...
2. ...

### 四、证据分析

逐份分析每项证据：

**证据名称** | 提交方 | 证明目的 | 三性分析 | 关联性评价
- **证明力评估**：强/中/弱/待补强
- **关键内容**：引用原文
- **与其他证据的关系**：印证/矛盾/补充/无关
- **存在问题**：形式瑕疵/内容矛盾/来源不明等

其中"三性分析"指：真实性、合法性、关联性。

### 五、证据链核对

- **已形成闭环的事实**：列出有多份证据相互印证的事实
- **证据链断裂点**：列出仅有孤证或证据相互矛盾的事实
- **待补证事项**：列出需要进一步收集证据的方向

### 六、法律适用分析

- 核心法律关系定性
- 适用法律法规及司法解释（列明具体条文）
- 争议焦点及双方可能的论据
- 类案检索提示（可建议关键词）

### 七、风险与机会

**不利因素（风险点）：**
1. ...
2. ...

**有利因素（突破口）：**
1. ...
2. ...

### 八、后续工作建议

- 需补充调取的证据
- 需进一步核实的事实
- 庭审准备要点
- 调解/和解可能性评估

## 适用场景

### 场景一：首次接手案卷

用户说"帮我阅卷"或提供案卷文件目录 → 完整执行第一步到第三步，生成完整阅卷报告。

### 场景二：针对特定问题阅卷

用户提出具体问题（如"这份合同有没有漏洞"、"证据是否充分"）→ 仅执行相关部分，聚焦用户关注点，但仍需标注文件和来源。

### 场景三：核对证据链

用户要求"核对证据链" → 重点执行第四步和第五步，绘制证据关系图（文字描述即可）。

### 场景四：分析法律风险

用户要求"分析风险" → 重点执行第六步和第七步，从双方立场分别评估。

### 场景五：起草法律文书

用户要求基于案卷起草起诉状/答辩状/代理词 → 先确认阅卷报告已生成，再基于报告内容起草文书。

## 注意事项

- 引用案卷原文时必须加引号并标注出处（文件+页码/段落）
- 对案卷中不清晰、矛盾之处标注"存疑"而非自行推断
- 法条引用应列明法律全称、条文号、具体内容
- 如案卷量较大（>20 份文件），建议分批处理，每批不超过 10 份
- 报告使用中文撰写，专业术语可附英文对照

## 文件类型支持

支持阅读以下常见案卷格式：
- PDF（扫描件/电子版）
- Word 文档（.docx / .doc）
- 文本文件（.txt / .md）
- 图片（.png / .jpg / .tiff — 含扫描件）
- 网页/HTML 格式的裁判文书

遇到图片类文件时，使用 Read 工具读取（支持图片视觉分析，可提取扫描件中的文字）。
