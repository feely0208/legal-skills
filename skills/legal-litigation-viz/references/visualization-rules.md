# 诉讼可视化规则

## 一、画什么

| 图 | 回答的问题 | 不画什么 |
|---|---|---|
| 时间轴 | 什么时候发生了什么，谁做的，有没有证据 | 心理活动、推测动机、没有日期的"长期" |
| 法律关系图 | 谁和谁之间是什么关系，谁是担保人/实际用款人 | 与本案无关的第三方、公司内部架构 |
| 证据矩阵 | 每份证据能证明哪个待证事实，缺哪格 | 证据的全文、质证意见全文 |
| 争点对照 | 双方争什么，各自靠什么证据，庭前要补什么 | 法官倾向、胜诉率预测 |

## 二、三档重要性怎么判

- 🔴 关键：直接决定一个要件成立/不成立、影响诉讼时效、影响金额计算、或者是对"自认"的固定。
- 🟡 辅助：支持某个事实，但单独不足以证明；或用于弹劾对方陈述。
- ⚪ 背景：交代人物/交易背景，不影响要件。

判断口径：**删掉这条，要件还成立吗？** 成立 → 🟡/⚪；不成立 → 🔴。

## 三、原告/被告视角差异

同一件事，两边标红的不一样：

| 事件 | 原告视角 | 被告视角 |
|---|---|---|
| 借款到期未还 | 🔴（违约、起算时效） | 🟡（承认到期但主张已还/抵销） |
| 对方微信承认"再宽限" | 🔴（自认/时效中断） | 🔴（需要解释或质疑真实性） |
| 现金交付无凭证 | 🔴（举证缺口） | 🔴（主攻点） |

视角要显式写在 `side`，图上方会标注；不要两边都用同一套红点。

## 四、常见画错

1. **时间倒挂**：按材料顺序而不是日期排。渲染器会按日期排序，但"2024年5月"和"2024-05-01"混用会排错，统一格式。
2. **证据编号对不上**：`proves` 写了不存在的事实 id，矩阵会出现整行"—"。
3. **把分析塞进事实**：`fact` 里写"被告恶意拖欠"——这是结论，不是事实。事实写"到期后未还款"，结论放 `issues.ours`。
4. **关系图变成人物介绍**：只画有法律意义的关系（合同、借贷、担保、侵权、代理），不画"朋友""同事"。
5. **争点写成诉请**："判令被告还款"是诉请，不是争点；争点是"借贷合意是否成立""款项是否交付"。
6. **缺口不写**：图看起来完整，庭上被问住。缺口必须进 `gaps`，这是可视化的价值之一。

## 五、交付检查

- [ ] 每条 🔴 有证据编号
- [ ] 日期格式统一、无倒挂
- [ ] 证据矩阵无空行
- [ ] 争点覆盖双方核心主张
- [ ] 页脚保留复核声明

## 六、Schema 字段详解

| 字段 | 必填 | 说明 | 常见错误 |
|---|---|---|---|
| `title` | 是 | 案件名，用于标题和文件名 | 写成「案件」两个字 |
| `caseNo` | 否 | 案号，一审/二审写全 | 只写数字 |
| `side` | 是 | `plaintiff` / `defendant` / `neutral` | 空着导致配色按中立处理 |
| `summary` | 否 | 一句话案情，别超过 60 字 | 写成代理词 |
| `parties[].id` | 是 | 短 id，供 relations 引用 | 用中文全名当 id，改起来麻烦 |
| `parties[].role` | 是 | 原告/被告/第三人/担保人/证人 | 只写名字不写角色，图上颜色分不出 |
| `events[].significance` | 建议 | 🔴/🟡/⚪ | 全部标红，等于没有重点 |
| `facts[].id` | 是 | 待证事实编号 F1/F2 | 与 evidence.proves 对不上 |
| `evidence[].proves` | 是 | 对应 facts 的 id 数组 | 填了事实描述而不是 id |
| `issues[].point` | 是 | 争点，不是诉请 | 「判令还款」不是争点 |
| `gaps[]` | 建议 | 缺口/待补，字符串数组 | 空着，让图看起来「很完整」 |

## 七、按案件类型的画法

### 民间借贷
- 时间轴重点：借款合意、实际交付、到期、催告、部分还款；
- 关系图：出借人 → 借款人；有担保的加担保人，注明一般/连带；
- 证据矩阵：借条（合意+金额）、转账（交付）、聊天（催告/自认）；
- 高频缺口：现金交付无凭证、利息约定不明、还款冲抵顺序。

### 买卖合同
- 时间轴：下单、发货、签收、验收、对账、催款；
- 关系图：买方、卖方、实际收货人、担保方；
- 证据矩阵：合同、订单、物流签收、对账单、发票；
- 高频缺口：签收人无权代理、验收标准未约定、质量异议期。

### 劳动争议
- 时间轴：入职、调岗/降薪、争议行为、解除通知、仲裁申请；
- 关系图：劳动者、用人单位、派遣/外包单位；
- 证据矩阵：劳动合同、工资流水、考勤、解除通知、规章制度签收；
- 高频缺口：规章制度未经民主程序、考勤原始记录缺失。

### 侵权/人身损害
- 时间轴：侵权行为、报警/就诊、鉴定、协商；
- 关系图：受害人、侵权人、保险公司、雇主；
- 证据矩阵：事故认定书、病历、票据、鉴定意见；
- 高频缺口：因果关系、参与度、误工证明。

### 建设工程
- 时间轴：合同、开工、签证、停工、验收、结算、催款；
- 关系图：发包人、承包人、实际施工人、分包；
- 证据矩阵：施工合同、签证单、验收记录、结算书、付款记录；
- 高频缺口：签证无甲方签字、实际施工人身份证据。

## 八、三种汇报场景怎么用

| 场景 | 用哪几张图 | 讲解顺序 |
|---|---|---|
| 当事人首次沟通 | 时间轴 + 关系图 | 先讲发生了什么，再讲谁欠谁 |
| 团队庭前会 | 证据矩阵 + 争点对照 | 先看缺口，再分任务 |
| 法官/调解 | 时间轴 + 关键证据 | 一页纸讲完，不展开枝节 |

## 九、打印与配色

- 默认 A4 纵向，页边距 14mm；关系图太宽时在浏览器里选横向；
- 原告蓝、被告橙、中立灰——不要用红绿区分原被告（红绿在打印/色弱下不可靠）；
- 🔴 只用于「删掉它要件就不成立」的事件，一页超过 5 个红点就说明没排序；
- 提交法院的版本建议黑白打印一次，确认没有靠颜色才能读懂的信息。
