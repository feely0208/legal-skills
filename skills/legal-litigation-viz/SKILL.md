# 诉讼可视化技能

## 这个技能解决什么

案卷读完了，脑子里有画面，但讲给当事人、法官、团队听时还是"一堆字"。诉讼可视化不是画得好看，是**把事实、证据、争点放到同一张图上**，让缺口和矛盾自己显形。

本技能做四张图，全部输出为一个可打印的单文件 HTML：

1. **时间轴**：谁在什么时候做了什么，哪条有证据，哪条是红的；
2. **法律关系图**：当事人、担保人、标的物之间的箭头；
3. **证据矩阵**：每份证据能证明哪个待证事实，缺哪一格；
4. **争点对照**：我方主张 vs 对方抗辩 vs 对应证据 vs 准备提示。

## 界面能力（v2）

- 左侧目录 + 顶部页签：时间轴 / 法律关系 / 证据矩阵 / 争点对照 / 证据缺口；
- 时间轴按年分组，支持「关键 / 辅助 / 有证据 / 无证据」筛选与关键词搜索；
- 关系图曲线边、箭头方向、悬停高亮、缩放（右上按钮或 Ctrl+滚轮）；
- 证据矩阵：事实覆盖率进度条、每列证据份数、零证据事实标红、首列吸附；
- 争点用卡片呈现「我方 vs 对方 + 证据 + 准备提示」；
- 一键打印 / 导出 PDF，打印时自动展开全部视图。

## 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 庭前梳理、客户汇报、团队案件讨论 | 只要文字版阅卷笔录 → `legal-evidence-review-notes` |
| 证据很多、时间线乱、关系复杂 | 只要证据目录 → `legal-evidence-catalog` |
| 需要向法官/客户讲清"谁欠谁、什么时候、凭什么" | 只要类案对比 → `legal-claim-chart` |
| 检查证据缺口与争点准备 | 只要算钱 → `legal-damages-calc` |

## 输入

必需：

1. 案件材料：起诉状/答辩状/合同/聊天记录/转账/判决书等（.docx/.pdf/.md/.txt）；
2. 视角：原告 / 被告 / 中立（决定重要事件的配色与取舍）；
3. 案件名称（用于文件名与标题）。

可选：案号、争议金额、开庭时间、已知争点。

材料不全时：先出图，把缺的放在 `gaps` 里，不要脑补。

## 工作流程

### 第零步：读法律档案

先读 `~/.deepwhale/深鲸法律档案.md`；不存在就把 `templates/法律档案.md` 复制过去再问。视角没填时不要假设。

### 第一步：抽四类要素

逐份读材料，只抽这些，不写分析：

| 要素 | 从哪来 | 例子 |
|---|---|---|
| 时间 | 合同签署日、转账日、聊天时间、判决日期 | 2024-05-01 |
| 主体 | 谁做的 | 李某 |
| 行为/事实 | 做了什么 | 借款 20 万元并出具借条 |
| 证据 | 哪份材料能证明 | E1 借条 |

日期统一成 `YYYY-MM-DD`；只有年月的写 `YYYY-MM`；完全没有的放"时间待定"，不要编。

### 第二步：结构化（核心）

按下面 schema 写 `case.json`（字段可少，不能编）：

```json
{
  "title": "张某诉李某民间借贷纠纷",
  "caseNo": "（2026）浙0302民初1234号",
  "side": "plaintiff",
  "summary": "一句话案情",
  "parties": [{"id": "p1", "name": "张某", "role": "原告"}],
  "relations": [{"from": "p1", "to": "p2", "label": "民间借贷"}],
  "events": [{"date": "2024-05-01", "actor": "李某", "fact": "借款 20 万元", "evidence": ["E1"], "significance": "🔴"}],
  "facts": [{"id": "F1", "text": "借贷合意"}],
  "evidence": [{"id": "E1", "name": "借条", "proves": ["F1"], "status": "已取得"}],
  "issues": [{"point": "是否存在借贷合意", "ours": "...", "theirs": "...", "evidence": ["E1"], "tip": "..."}],
  "gaps": ["现金 5 万元缺少取现记录"]
}
```

规则：

- `significance` 只有三档：🔴 关键（直接影响要件/时效/金额）、🟡 辅助、⚪ 背景；
- 同一事件有多份证据就写多个编号；
- `proves` 只能填 `facts` 里存在的 id；
- 拿不准的事实放 `gaps`，不要塞进 `events`。

### 第三步：渲染

```bash
node scripts/render-cli.mjs case.json -o "张某诉李某-诉讼可视化.html"
```

输出是单文件 HTML（内联 CSS/SVG），双击就能开、可直接打印 A4，不依赖网络与 CDN。

### 第四步：交付前自检

- [ ] 每条 🔴 事件都有证据编号，没有的已放进 gaps；
- [ ] 时间轴顺序正确，没有"判决在前、借款在后"这类倒挂；
- [ ] 证据矩阵里每份证据至少对应一个事实，或明确标"程序性材料"；
- [ ] 争点覆盖起诉状/答辩状的核心主张；
- [ ] 页脚保留"不构成法律意见、提交前须核对原件"。

## 输出规范

- 文件名：`<案件名>-诉讼可视化.html`；
- 同时保留 `case.json`（下次改图只改 JSON，不重画）；
- 需要 Word/PDF 版本：先用浏览器打印成 PDF，或用 `chinese-doc-formatter` 排文字版说明。

## 质量闸门

- 不编日期、金额、当事人、案号；
- 不把推测写成事实；推测放 `issues.tip` 或 `gaps`；
- 原告/被告视角只改"重要性标记"和措辞，不改事实；
- 图里出现的每个编号都能在 `facts`/`evidence` 里找到。
