# 类案争点对比表技能

## 这个技能解决什么

律师手里常有一叠「看起来都相关」的判决，真到写代理意见时却用不上：没人说得清这几份判决到底在哪个争点上一致、哪个争点上打架，打架是因为法条改了、地域不同，还是因为事实本来就不一样。

本技能不做「类案检索」（那是 `legal-research` 的事），而是把已经拿到手的判决**拆成争点矩阵**：同一行是同一个法律问题，同一列是一份判决。填完就能看出：哪一格是空白的（没人判过）、哪几格互相矛盾（同案不同判）、哪些矛盾其实是事实差异造成的假冲突。

## 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 手上已有 2–5 份判决，要比对裁判口径 | 还没找到判决，只要检索关键词和路径 → `legal-research` |
| 要判断「我方主张有没有判决支持、风险多大」 | 要核对文书里已引用的案号、法条真假 → `legal-cite-check` |
| 要写「同案不同判」的说明或上诉理由 | 要起草上诉状正文 → `legal-appeal` |
| 二审/再审前梳理原审与上级法院的分歧 | 要出正式法律意见书 → `legal-opinion` |
| 要给客户解释「为什么类似案子判得不一样」 | 要把判决书内容做成证据清单 → `legal-evidence-catalog` |

边界：本技能**只做对比，不做胜负判断**。矩阵里的「倾向」是描述性统计，不是对本案结果的预测。

## 输入

**必需**

1. 判决材料：2–5 份，`.md` / `.txt` / `.docx` / `.pdf` 路径或摘要。只有摘要时必须标「摘要级」，并降级其引用价值。
2. 本案争点：争议焦点，或按请求权基础拆出的争点。只给「事实」时，先拆争点让用户确认，不替法院归纳。
3. 本案基本事实：时间、主体、合同关键条款、已履行部分、证据状况。
4. 立场：代理原告 / 被告 / 中立评估。决定输出第 6 节「可用性判断」怎么写。

**可选**：本案已有的起诉状、答辩状、庭审笔录、鉴定意见；希望重点比对的争点。

**缺失时逐项追问。** 尤其三样不能猜：判决的审级与裁判日期（决定可比性）、本案争点（决定矩阵的行）、立场（决定建议方向）。

## 工作流程

### 第零步：读法律档案

先读 `~/.deepwhale/深鲸法律档案.md`。不存在时，把仓库里的 `templates/法律档案.md` 复制过去，再逐项问用户：角色（律师/法务/当事人）、立场、执业地域、行文风格、风险偏好、升级链。档案里没填的，不要假设。

档案里的「执业地域」直接影响第五步的可比性判断（本省/本市判决权重更高），不要跳过。

### 第一步：材料预检

对每份判决先回答三个问题，答不上就列为待补：

| 检查项 | 不合格的表现 | 处理 |
|---|---|---|
| 能否定位说理段 | 只有「本院认为」的转述，没有原文 | 标「摘要级」，矩阵里依据栏写【待补：原文段落】 |
| 案号/法院/日期是否齐全 | 缺裁判日期或审级 | 标【待补】，不进入「高可比」组 |
| 是否同一争点 | 案由相同但争点不同 | 换争点或剔除，不做「案由相同即类案」的偷懒对比 |
| 是否 OCR/扫描件 | 关键数字模糊、错位 | 提示核对金额/日期/比例；OCR 错一位，整张表都错 |

### 第二步：定争点（矩阵的行）

争点从**本案的请求与抗辩**拆，不从判决书里抄。方法见 `references/issue-and-comparability.md` 第一、二节。

1. - 每个争点写成**可判断的命题**，不是一个话题。
     - ❌「违约金问题」 → ✅「约定违约金是否过分高于实际损失」
- 按「请求 → 抗辩 → 要件」三层拆，主争点编号 `I1`，子争点 `I1.1`。
- 争点数控制在 3–7 个。超过说明拆得太碎，合并同义项。
- 定完先给用户确认再填表——争点错了，整张表白做。

### 第三步：逐份抽要素（判决台账）

每份判决抽 10 项，先做台账再做矩阵：

法院 / 案号 / 裁判日期 / 程序（一审·二审·再审·简易·普通）/ 案由 / 诉讼请求 / 争议焦点 / 法院认定 / 裁判要旨 / 裁判结果。

- **摘原文，不改写。** 法院认定一栏放判决原文（可截断，用「……」），另起一句写自己的归纳，两者视觉上分开。
- 每个认定标位置：`第 X 页` / `第 X 段` / `本院认为第 X 项`。定位不到就写【待补：段落位置】。
- 裁判结果写**主文**（全部支持/部分支持/驳回），不写「胜诉」「败诉」这种含糊说法。
- 抽取清单和常见漏项见 `references/judgment-extraction.md`。

### 第四步：填矩阵（本技能的核心）

行是争点，列是判决。每格固定三行：

```
✅ 支持（或 ❌ 不支持 / ⚠️ 部分支持 / ➖ 未涉及）
认定：一句话结论
依据：判决第 X 段；《民法典》第 XXX 条（条号待核）
```

极性判定只认**法院说理或主文**，不认当事人主张，也不认「本院查明」里的事实描述。四种极性：

| 标记 | 含义 | 判定标准 |
|---|---|---|
| ✅ | 支持该争点上的主张 | 说理明确采纳，或主文体现 |
| ❌ | 不支持 | 说理明确否定 |
| ⚠️ | 部分支持 / 附条件 | 支持但有前提、比例或范围限制 |
| ➖ | 未涉及 | 判决未审理该争点，或已调解结案 |

**同一争点在不同判决里极性不同，就是冲突。** 不要为了「看起来整齐」把 ⚠️ 写成 ✅。

### 第五步：判可比性（决定哪些能用）

四个维度，各给「高 / 中 / 低」加一句理由，再看综合：

| 维度 | 高 | 低 |
|---|---|---|
| 审级 | 二审、再审、指导性案例、入库案例 | 基层一审、且无上级维持 |
| 地域 | 本案管辖法院所在省/市 | 外省且无统一裁判尺度 |
| 时间 | 法律与司法解释未变，裁判日期相近 | 跨越法律修订、新解释施行 |
| 事实 | 合同条款、履行状态、证据结构接近 | 关键事实不同（有无约定、有无鉴定） |

综合可比性 = 四维里最低的一维决定上限，不是取平均。**低可比判决仍可入表，但只能进「背景参考」，不能进「可用依据」。**

### 第六步：写「同案不同判提示」

这是本技能最值钱的部分，不能只列冲突，要给归因。表头固定：`争点｜判决 A｜判决 B｜分歧性质｜可能原因｜对本案影响｜处理建议`。

- **分歧性质**三选一：法律适用分歧 / 事实认定分歧 / 裁量分歧。选错会导致建议方向全错。
- **可能原因**从这几个里找，并写明依据：法律或司法解释修订、地域裁判尺度、审级效力（上级法院与指导性案例优先）、事实差异（条款、履行、证据）、自由裁量区间。
- **不裁判谁对。** 写「A 的说理更完整 / B 的事实更接近本案」，不写「A 判错了」。
- **处理建议**用三档：可用 / 慎用（需区分）/ 不用。要给「区分路径」（distinguishing）：本案哪个事实点可以把不利判决区分开。若冲突无法用上述原因解释，写「存在真实裁判分歧，建议检索上级法院或更高层级案例」，不要硬编理由。

## 输出规范

主文件 `claim-chart.md`，固定七节，结论先行：

1. 结论摘要（3–5 条：哪个争点有共识、哪个有分歧、我方风险点）
2. 判决台账（10 要素表）
3. 争点矩阵（核心表）
4. 可比性评估（四维表 + 综合结论）
5. 同案不同判提示（冲突表 + 归因）
6. 可用性判断（按立场：可用 / 慎用 / 不用，各附一句理由）
7. 待补清单与风险分级（🔴/🟡/⚪）

「同案不同判提示」默认并入 md 第 5 节；需单独给客户或合伙人看时，另存 `同案不同判提示-<主题>.md`，只留冲突表、归因与建议。

同时输出 `claim-chart.csv`，供 Excel / 排序 / 拼表：

- 编码 UTF-8 **带 BOM**，否则 Excel 打开中文乱码；
- 列：`争点编号,争点,判决标识,法院,案号,裁判日期,程序,极性,法院认定,裁判要旨,依据位置,可比性`；
- 字段含逗号、引号、换行时用双引号包裹，内部引号双写；
- 一个「争点 × 判决」一行，未涉及的也要出空行（极性写「未涉及」），不要省略——省略就看不出空白格。

需要正式交付时，用 `chinese-doc-formatter` 转 `.docx` / `.pdf`。转换后仍需人工核对案号与段落位置。

文件放在本次工作目录，命名 `claim-chart-<主题>-<YYYYMMDD>.md`。末尾固定：

```
依据：第 2 节判决台账、第 3 节争点矩阵（逐格标注段落位置）
声明：AI 辅助生成，需承办律师复核；矩阵只描述已收集判决的裁判情况，不预测本案结果。
```

## 质量闸门（交付前自检）

- [ ] 每份判决的法院、案号、裁判日期、审级齐全；缺失项已标【待补】，没有编造
- [ ] 争点是从本案请求/抗辩拆出的命题，不是抄判决书的「争议焦点」原句
- [ ] 矩阵每格都有极性 + 认定 + 依据位置；没有「未涉及」被写成「不支持」
- [ ] 极性依据来自法院说理或主文，不是当事人主张或「本院查明」
- [ ] 可比性四维逐项给了理由，综合取最低维，没有用「都是买卖合同纠纷」一句带过
- [ ] 冲突表写清分歧性质（法律适用/事实认定/裁量），归因有依据
- [ ] 没有断言哪份判决「判错了」，没有承诺本案结果
- [ ] 没有编造案号、法条条号、金额、日期；不确定的条号标「待核」
- [ ] CSV 带 BOM，一个争点一行，含未涉及项
- [ ] 输出带「AI 辅助生成，需承办律师复核」标识
- [ ] 提示了「提交法院前须核对判决原文与最新效力状态」

## 输出示例

```markdown
# 类案争点对比表：质量异议期届满后能否拒付货款（节选）

### 一、结论摘要
1. 争点 I1（检验期届满后能否以质量瑕疵拒付）在两份一审判决中结论相反，属**事实认定分歧**，不是法律适用分歧。
2. 两份判决均以检验期限规则为裁判依据（第 621 条、第 622 条），分歧在于「瑕疵是否属于隐蔽瑕疵、能否突破检验期」。
3. 我方代理买方：判决 B 的区分路径可用，但需补【待补：设备功能缺陷的鉴定或卖方自认证据】。
4. 🔴 两份均为基层一审，无可比性更高的上级判决，结论稳定性低。

### 三、争点矩阵
| 争点 | 判决 A（甲市乙区，2023-04） | 判决 B（甲市丙区，2023-12） |
|---|---|---|
| I1 检验期届满后能否以质量瑕疵拒付 | ❌ 不支持<br>认定：逾期未提异议，视为质量符合约定<br>依据：第 621 条；判决 A 第 5 段 | ⚠️ 部分支持<br>认定：属隐蔽瑕疵，自发现时起算合理期限<br>依据：第 622 条（检验期仅及外观瑕疵）、第 621 条第 2 款；条号待核；判决 B 第 7 段 |
| I2 减价幅度如何确定 | ➖ 未涉及 | ✅ 按缺陷部件占比酌减<br>依据：判决 B 第 8 段 |

### 五、同案不同判提示
| 争点 | A | B | 分歧性质 | 可能原因 | 对本案影响 | 建议 |
|---|---|---|---|---|---|---|
| I1 | 不支持 | 部分支持 | 事实认定分歧 | A 案瑕疵在收货时肉眼可见；B 案缺陷在调试后显现，且有卖方工程师微信确认 | 本案缺陷在安装后 3 个月显现，接近 B 案 | 可用 B，但须证明「非肉眼可查」 |

依据：第 2 节判决台账、第 3 节争点矩阵
声明：AI 辅助生成，需承办律师复核；不预测本案结果。
```
