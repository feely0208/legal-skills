# 合同草拟技能

以中国执业律师视角，根据用户需求草拟完整、合法、规范的合同文本，最终在桌面生成一个以合同名命名的文件夹，内含 Word 合同文档、Markdown 合同文本和起草说明。

## 完整工作流程

### 第零步：收集起草需求

与用户确认以下核心信息（信息不足时应主动询问）：

#### 必须确认的信息

| 信息项 | 说明 |
|--------|------|
| 合同类型 | 买卖/借款/租赁/建工/委托/保证/股权转让/劳动/技术/抵押质押/其他 |
| 当事人信息 | 甲方/乙方（及其他参与方）的全称、地址、法定代表人/身份证号、联系方式 |
| 核心交易条款 | 标的、价款/报酬、履行期限、履行方式等核心商业条款的具体内容 |
| 用户立场 | 用户是甲方还是乙方？（据此调整保护性条款的倾斜方向） |

#### 选填信息（有则提供，无则使用标准模板）

| 信息项 | 说明 |
|--------|------|
| 特殊约定 | 任何超出标准模板的特殊需求，如分期付款、所有权保留、竞业限制等 |
| 参考文件 | 对方提供的合同草案、谈判备忘录、意向书等 |
| 行业背景 | 涉及特殊行业的，行业惯例和监管要求 |
| 签约地点 | 合同签订地（影响争议解决管辖地选择） |

**信息收集策略**：
- 如果用户已经提供了足够的信息，直接开始草拟
- 如果关键信息缺失（如当事人、价款、标的），一次性列出所有待确认项询问
- 不要逐条询问，应批量收集

### 第一步：确定合同类型与结构

| 合同类型 | 主要法律依据 | 法定必备条款 | 核心保护性条款 |
|---------|-------------|-------------|---------------|
| 买卖合同 | 《民法典》第595-647条 | 标的、数量、质量、价款、履行期限/地点/方式、违约责任 | 所有权保留、检验期间、风险转移、质保 |
| 借款合同 | 《民法典》第667-680条 + 民间借贷司法解释 | 币种、数额、利率、期限、还款方式、违约责任 | 担保条款、提前还款、禁止预扣利息声明 |
| 建设工程合同 | 《民法典》第788-808条 + 建工司法解释 | 工程范围、工期、质量、价款、验收、拨款结算 | 优先受偿权、签证索赔、竣工验收、质量保修 |
| 租赁合同 | 《民法典》第703-734条 | 租赁物、租金、租期、用途、维修义务 | 转租限制、添附物归属、优先购买权、买卖不破租赁 |
| 委托合同 | 《民法典》第919-936条 | 委托事项、权限范围、委托费用/报酬、履行期限 | 转委托限制、任意解除权赔偿、注意义务标准 |
| 保证合同 | 《民法典》第681-702条 + 担保制度解释 | 被担保主债权、保证方式（一般/连带）、保证范围、保证期间 | 追偿权、主合同变更的影响、公司担保决议声明 |
| 股权转让 | 《民法典》合同编 + 《公司法》 | 标的股权、转让价款、支付方式、交割条件、陈述与保证 | 或有负债、过渡期损益、优先购买权声明、竞业禁止 |
| 劳动合同 | 《劳动合同法》全文 | 合同期限、工作内容/地点、工作时间/休假、报酬、社保、劳动保护 | 试用期、竞业限制+补偿、保密、服务期违约金、解除条件 |
| 技术合同 | 《民法典》第843-887条 | 项目名称、内容/要求、经费/报酬、履行计划、验收标准、成果归属 | 后续改进归属、风险分担、保密范围与期限、侵权责任 |
| 抵押/质押 | 《民法典》第394-458条 | 被担保债权、担保物、担保范围、实现方式 | 登记/交付要件、禁止流押流质、担保物价值维持、保险 |

**务必同时阅读 `references/contract_drafting_guide.md` 获取每类合同的详细起草模板和示范条款。**

### 第二步：四层递进起草

#### 第一层：法定必备条款（《民法典》第470条）

根据合同类型，确保以下核心条款完整：

1. **当事人信息**：姓名/名称、住所、法定代表人/身份证号、统一社会信用代码、联系电话/邮箱
2. **标的**：名称、规格/型号、数量、权属状态、无权利负担声明
3. **价款/报酬**：金额（大写+小写）、币种、计价方式、税费承担
4. **履行**：时间、地点、方式、期限、验收标准和程序
5. **违约责任**：违约情形、违约金计算方式、赔偿范围、免责事由
6. **争议解决**：协商→调解→诉讼/仲裁，管辖法院/仲裁机构

#### 第二层：通用必要条款

1. **合同生效**：签署/盖章生效、附条件/附期限生效（《民法典》第158-160条）
2. **合同变更与解除**：变更程序、约定解除条件、解除后果处理（《民法典》第562-566条）
3. **不可抗力**：定义范围、通知义务、后果分担（《民法典》第180、590条）
4. **通知送达**：双方地址、通知方式（书面/邮件/传真）、视为送达的条件
5. **保密条款**：保密信息定义、保密期限、例外情形、违约责任
6. **合同份数**：正本份数、各执份数、同等效力声明

#### 第三层：类型化专项条款

查阅 `references/contract_drafting_guide.md` 获取对应类型的完整条款模板。关键专项条款包括：

| 合同类型 | 专项条款 |
|---------|---------|
| 买卖 | 包装标准、检验期间与异议期、质保期、售后服务、所有权保留 |
| 借款 | 利率约定（≤LPR四倍）、支付方式、提前还款、担保从合同 |
| 建工 | 资质保证、项目经理、工期延误、工程变更签证、竣工验收、质量保修、安全责任 |
| 租赁 | 转租权、装修装饰物处理、维修义务分配、续租条款 |
| 委托 | 转委托、报告义务、费用预付、留置权 |
| 保证 | 保证方式明确（默认为一般保证！）、保证期间明确、主合同变更处理 |
| 股权转让 | 交割先决条件、过渡期安排、陈述与保证清单、赔偿上限与下限 |
| 劳动 | 试用期合法长度、竞业限制（范围+期限+补偿）、服务期违约金限制、规章制度告知 |
| 技术 | 技术成果验收标准、后续改进成果归属、风险通知义务、技术资料交付 |
| 抵押/质押 | 登记/交付时间节点、担保物保管、价值维持与补充担保、实现方式 |

#### 第四层：用户立场的保护性倾斜

根据用户的交易地位，在以下方面进行合理倾斜（但不得显失公平）：

| 用户立场 | 可倾斜方向 |
|---------|-----------|
| **买方/委托方/发包方/雇主/债权人** | 更严格的验收标准、更长的质保期、更灵活的解除权、有利的管辖地 |
| **卖方/受托方/承包方/雇员/债务人** | 价款支付保障、责任上限条款、更窄的免责范围、有利的管辖地 |

**倾斜原则**：
- 单次倾斜不超过合理商业范围（避免被认定为显失公平——《民法典》第151条）
- 在起草说明中标注倾斜条款，提醒用户谈判时注意
- 违约金比例双方对等，差异过大可能在诉讼中被调减（《民法典》第585条）

### 第三步：质量检查

#### 3.1 法律合规检查

- [ ] 法定必备条款是否完整
- [ ] 利率、违约金、试用期等法定上限是否遵守
- [ ] 是否存在违反效力性强制性规定的条款
- [ ] 格式条款是否有合理提示
- [ ] 保证方式是否明确（不写明默认为一般保证）

#### 3.2 语言精确性检查

- [ ] 金额大小写是否一致
- [ ] 时间节点是否明确（具体日期 or 明确的天数/工作日）
- [ ] "合理期限""及时""重大"等模糊用语是否已量化
- [ ] 指代是否一致（同一主体前后名称是否统一）
- [ ] "和/或""包括但不限于"等用语使用是否恰当

#### 3.3 条款一致性检查

- [ ] 前后条款是否存在矛盾或冲突
- [ ] 定义条款中的定义与实际使用是否一致
- [ ] 违约责任条款是否覆盖了所有义务条款
- [ ] 争议解决条款是否与通知送达条款衔接

#### 3.4 完整性检查

- [ ] 签署栏信息是否完整（名称、授权代表、日期）
- [ ] 附件清单是否列明
- [ ] 合同份数是否说明

### 第四步：生成全部输出文件

从合同名称提取文件夹名，在桌面创建：


例如合同名为 `XX采购合同`，文件夹名为 `XX采购合同`。

#### 4.3 生成文件

```bash

python "<skill目录>/scripts/generate_contract_docx.py" \
  --input "/tmp/contract_draft.json" \
  --output "~/Desktop/<合同名称>/<合同名称>.docx"

# Markdown 合同文本和起草说明由 AI 直接生成
```

#### 4.4 生成 Markdown 合同文本

在桌面文件夹中写入 `合同名称.md`，包含完整的合同文本（Markdown格式）。

#### 4.5 生成起草说明

在桌面文件夹中写入 `起草说明.md`，包含：

1. **合同类型与法律依据**
2. **核心条款说明**：逐条解释重要条款的设置理由和法律依据
3. **保护性条款提示**：标注哪些条款是为用户利益特别设置的
4. **风险提示**：提示可能的争议点和对方可能挑战的条款
5. **谈判策略建议**：底线条款 vs 可让步条款
6. **签署注意事项**：签章要求、附件、见证等

#### 4.6 输出文件清单

最终桌面文件夹包含：

| 文件 | 说明 |
|------|------|
| `<合同名称>.docx` | 专业排版的Word合同文档（封面+正文+签署页） |
| `<合同名称>.md` | Markdown格式的合同全文（可在任何编辑器查看） |
| `起草说明.md` | 法律依据、条款说明、风险提示、谈判建议 |

#### 4.7 告知用户

输出完成后告知用户：
- 文件夹路径
- 每个文件的用途
- 建议首先查看 `起草说明.md` 了解合同设计思路，再用 `.docx` 文件对外发送
- 提醒本文件由AI生成，建议律师复核后使用

## JSON 注意事项

JSON 字符串值内部的引号必须用 `「」` 或 `『』`，严禁用 `""`（会被转成 ASCII 引号导致解析失败）。

正确：`"甲方从乙方处购买「标的物」"`
错误：`"甲方从乙方处购买\"标的物\""`

长文本内容（如 clause content）中的换行使用 `\n`，多个段落用 `\n\n` 分隔。

## 草拟原则

### 必须做到

1. **法条依据准确**：每个核心条款的设计要有现行法律依据，不确定时标注"根据相关法律规定"
2. **条款完整可用**：合同应是一份可直接使用的完整文本，不是条款框架
3. **语言精确严谨**：避免模糊表述，关键要素量化
4. **格式规范**：符合中国法律文书的排版习惯（标题黑体二号、正文仿宋三号等）
5. **保护用户利益**：在合法范围内最大限度保护用户利益
6. **风险提示到位**：在起草说明中如实告知潜在风险和对方可能的反驳点
7. **覆盖所有必备条款**：不得遗漏法定的合同必备条款
8. **保证方式明确**：保证合同必须明确"一般保证"或"连带责任保证"，不写则默认为一般保证

### 禁止事项

- 不得编造不存在的法条编号
- 不得遗漏法定必备条款
- 不得设置明显违法的条款（如流押流质条款、超法定上限的违约金/利率/试用期）
- 不得使用"按照行业惯例""双方友好协商"等空洞表述替代具体约定
- 不得忽视合同的商业可行性而一味添加保护性条款
- 不得在双方权利义务上制造显失公平的局面
