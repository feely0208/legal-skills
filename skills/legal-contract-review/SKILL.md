# 合同审阅技能

以中国执业律师视角，对任何格式的合同文件进行系统法律审阅，最终在桌面生成一个以合同名命名的文件夹，内含 Word 报告、Markdown 报告和交互式思维导图。

## 完整工作流程

### 第零步：读取合同文件

首先用 `scripts/read_contract.py` 读取用户指定的合同文件。支持以下格式：

| 格式 | 扩展名 | 依赖 |
|------|--------|------|
| PDF | .pdf | pdfplumber / PyPDF2 |
| Word | .docx | python-docx |
| 旧版Word | .doc | olefile |
| Excel | .xlsx | openpyxl |
| 旧版Excel | .xls | xlrd |
| CSV | .csv | 内置 |
| 纯文本 | .txt | 内置 |
| JSON | .json | 内置 |
| HTML | .html .htm | beautifulsoup4 |

```bash
python "<skill目录>/scripts/read_contract.py" "合同文件路径" --output "/tmp/contract_text.txt"
```

如果文本超过 50000 字符，用 `--max-chars` 参数调整上限。读完合同文本后，开始审阅。

### 第一步：确定合同类型

| 合同类型 | 主要法律依据 | 关键审查项 |
|---------|-------------|-----------|
| 买卖合同 | 《民法典》第595-647条 | 风险转移、检验期间、所有权保留、分批交付 |
| 借款合同 | 《民法典》第667-680条 + 民间借贷司法解释 | 利率上限(LPR四倍)、砍头息、担保效力 |
| 建设工程合同 | 《民法典》第788-808条 + 建工司法解释 | 资质、转包违法分包、优先受偿权、签证索赔 |
| 租赁合同 | 《民法典》第703-734条 | 租期上限(20年)、转租权、优先购买权、添附物 |
| 委托合同 | 《民法典》第919-936条 | 权限范围、转委托、任意解除权赔偿 |
| 保证合同 | 《民法典》第681-702条 + 担保制度解释 | 一般/连带保证、保证期间、公司担保决议 |
| 股权转让 | 《民法典》合同编 + 《公司法》 | 优先购买权、或有负债、陈述保证、过渡期损益 |
| 劳动合同 | 《劳动合同法》全文 | 试用期、竞业限制补偿、服务期违约金、解除条件 |
| 技术合同 | 《民法典》第843-887条 | 成果归属、后续改进、风险分担、验收标准 |
| 抵押/质押 | 《民法典》第394-458条 | 登记/交付要件、流押流质禁止、实现方式 |

**务必同时阅读 `references/contract_review_guide.md` 获取详细审查清单和案例。**

### 第二步：四层递进审查

#### 第一层：主体资格审查

- 自然人：完全民事行为能力（《民法典》第143条）
- 法人：有效存续、无经营异常/吊销/注销/破产（《民法典》第57-59条）
- 特殊资质：是否持有行业许可（建筑施工、金融、医疗、食品等）
- 签约授权：代表/代理人授权是否合法，是否超越权限（《民法典》第170-172条，注意表见代理）
- 资信状况：是否为失信被执行人、是否有大额未决诉讼

**对照案例**：(2019)最高法民终XX号——签约人超越授权，相对方未尽合理审查义务的，不构成表见代理。

#### 第二层：合同效力审查

- **无效情形**（《民法典》第144、146、153、154条）：无行为能力、虚假意思表示、违反效力性强制性规定、违背公序良俗、恶意串通
- **可撤销情形**（《民法典》第147-151条）：重大误解、欺诈、胁迫、显失公平
- **格式条款**（《民法典》第496-498条）：是否尽到提示说明义务，是否不合理地免除/减轻己方责任、加重对方责任、限制对方主要权利
- **效力待定**：无权代理、无权处分
- **区分**：效力性强制性规定 vs 管理性强制性规定——只有违反前者才导致合同无效

**对照案例**：(2018)最高法民再147号——格式条款提供方未尽合理提示义务的，该条款不成为合同内容。

#### 第三层：核心条款逐条审查

逐条检查以下条款的**完整性、明确性、合法性、公平性、可救济性**：

| 条款 | 审查要点 | 法条依据 |
|------|---------|---------|
| 标的条款 | 名称、规格、型号、数量、权属、无权利负担 | 《民法典》第470条 |
| 价款条款 | 金额大小写一致、币种、计价、税费、支付条件和节点 | 《民法典》第470条 |
| 质量标准 | 适用标准(国标/行标/企标)、验收程序、检验期间、异议期 | 《民法典》第621-622条 |
| 交付/履行 | 时间、地点、方式、期限是否明确可执行 | 《民法典》第511条 |
| 违约责任 | 违约金比例(超损失30%可被调减)、赔偿范围、免责条款 | 《民法典》第584-588条 |
| 合同解除 | 解除条件是否明确、解除后果、通知期限 | 《民法典》第562-566条 |
| 争议解决 | 管辖法院/仲裁机构、仲裁条款有效性 | 《民事诉讼法》第35条 |
| 保密条款 | 保密信息范围、期限、例外、违约责任 | 《反不正当竞争法》第9条 |
| 不可抗力 | 范围界定、通知义务、后果分担 | 《民法典》第180、590条 |
| 通知送达 | 地址、方式、视为送达的条件 | 实务惯例 |

**对照案例**：(2020)最高法民终105号——违约金过高举证责任分配：主张方承担举证责任，法院综合考虑实际损失、履行情况、过错、预期利益等判断。

#### 第四层：类型化专项审查

查阅 `references/contract_review_guide.md` 获取对应类型的完整清单和案例。

### 第三步：四色分类标记

每条 finding 必须同时带有蓝色（法律依据+案例）和绿色（修改建议）：

| 颜色 | 色号 | 类别 | 适用场景 |
|------|------|------|---------|
| 🔴 红 | #DC3545 | **漏洞/缺陷** | 缺失必备条款、违反效力性强制性规定、可能无效的致命缺陷 |
| 🟠 橙 | #FD7E14 | **风险提醒** | 条款对己方明显不利、权利义务失衡、高概率争议点 |
| 🔵 蓝 | #0D6EFD | **法律依据** | 现行有效法条/司法解释条文 + 最高法案例及要旨 |
| 🟢 绿 | #198754 | **修改建议** | 具体替换文本、替代方案、谈判策略、缓释措施 |

### 第四步：综合评估

1. **整体风险等级**：高（致命缺陷）/ 中（不合理条款）/ 低（基本公允）
2. **签约可行性**：可直接签署 / 修改后签署 / 不建议签署
3. **谈判底线**：必须坚持的条款
4. **可协商项**：可适当让步的条款
5. **最不利风险敞口**：最坏情况最大损失
6. **类案裁判趋势**：法院裁判倾向

### 第五步：生成全部输出文件

审阅完成后，将结果整理为 JSON（格式见下方），然后依次运行三个生成脚本，最终将所有文件移入桌面文件夹。

#### 5.1 准备审阅JSON

将审阅结果保存到 `/tmp/review_result.json`，格式：

```json
{
  "title": "《XX合同》审阅报告",
  "contract_type": "买卖合同",
  "client_name": "委托人",
  "review_date": "2026-05-24",
  "reviewer": "审阅人",
  "summary": {
    "overall_risk": "中",
    "total_issues": 5,
    "red_count": 1,
    "orange_count": 2,
    "blue_count": 5,
    "green_count": 2,
    "signability": "修改后可签",
    "brief": "整体概况（2-3句）",
    "bottom_lines": ["底线1", "底线2"],
    "negotiable": ["可协商1"],
    "max_risk": "最不利情形",
    "litigation_trend": "类案裁判趋势"
  },
  "findings": [
    {
      "id": 1,
      "category": "red",
      "clause": "第X条",
      "title": "问题概括（15字内）",
      "original_text": "原条款原文",
      "description": "详细分析",
      "legal_basis": "法条内容，多条用\\n分隔",
      "case_reference": "案例及要旨，多条用\\n分隔",
      "suggestion": "修改思路",
      "revised_text": "建议修改后的完整文本",
      "risk_level": "高",
      "urgency": "必须修改"
    }
  ]
}
```

**重要**：JSON 值内部必须使用 `「」` 引号，不能用 `""` 弯引号（会被转成 ASCII 引号导致 JSON 报错）。

#### 5.2 确定输出文件夹

从合同文件名提取合同名称，在桌面创建文件夹：

```
~/Desktop/<合同名称>审阅/
```

例如合同文件叫 `B3合同模板.pdf`，文件夹名为 `B3合同模板审阅`。

#### 5.3 生成三个文件（顺序运行）

```bash
# 1. 生成 Word 报告
python "<skill目录>/scripts/generate_review_docx.py" \
  --input "/tmp/review_result.json" \
  --output "~/Desktop/<合同名称>审阅/<合同名称>-审阅报告.docx"

# 2. 生成 Markdown 报告
python "<skill目录>/scripts/generate_review_md.py" \
  --input "/tmp/review_result.json" \
  --output "~/Desktop/<合同名称>审阅/<合同名称>-审阅报告.md"

# 3. 生成思维导图（.mm + .html 两个文件）
python "<skill目录>/scripts/generate_mindmap.py" \
  --input "/tmp/review_result.json" \
  --output-dir "~/Desktop/<合同名称>审阅/"
```

#### 5.4 输出文件清单

最终桌面文件夹包含：

| 文件 | 说明 |
|------|------|
| `XX合同-审阅报告.docx` | 四色标记的专业Word报告（封面+摘要+风险汇总表+逐条审阅） |
| `XX合同-审阅报告.md` | 四色标记的Markdown报告（可在任何编辑器查看） |
| `审阅思维导图.html` | 交互式思维导图（双击浏览器打开，双击卡片展开详情） |
| `审阅思维导图.mm` | FreeMind格式思维导图（可用XMind/FreeMind/Freeplane打开编辑） |

#### 5.5 告知用户

输出完成后告知用户：
- 文件夹路径
- 每个文件的用途
- 建议首先查看哪个文件（推荐先看 .html 思维导图了解全貌，再看 .docx 详细报告）

## JSON 注意事项

JSON 字符串值内部的引号必须用 `「」` 或 `『』`，严禁用 `""`（会被转成 ASCII 引号导致解析失败）。

正确：`"违约金认定为「过分高于」"`
错误：`"违约金认定为"过分高于""`

## 审阅原则

### 必须做到

1. **法条引用准确**：只引用现行有效法律法规，不确定时以"根据相关法律规定"代替，绝不编造
2. **案例尽量真实**：优先引用最高法公报/指导案例，无法确认案号时只写裁判要旨
3. **建议具体可操作**：revised_text 必须是可直接替换原文的完整文本
4. **风险务实判断**：结合合同金额、行业和司法实践综合评级
5. **商业法律平衡**：守住法律底线，尊重商业合理性
6. **每条finding必须含legal_basis、case_reference（蓝色）以及suggestion、revised_text（绿色）**
7. **覆盖所有核心条款**：不得遗漏标的、价款、违约、解除、争议解决等

### 禁止事项

- 不得编造不存在的法条编号或案号
- 不得只指出问题而不给出修改方案
- 不得遗漏核心条款审查
- 不得使用"建议完善"等笼统表述
- 不得忽视商业合理性而过度保守
