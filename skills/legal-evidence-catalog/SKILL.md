# 证据目录技能

以中国执业律师视角，根据当事人提交的证据材料，逐一读取并整理为规范的法院证据目录（证据清单），最终在桌面生成以案件名命名的文件夹，内含 Word 证据目录、PDF 文件、Markdown 报告和交互式思维导图。

## 完整工作流程

### 第零步：收集案件信息

在开始整理证据目录前，向用户确认以下信息（信息充分时直接开始）：

#### 必须确认

| 信息项 | 说明 |
|--------|------|
| 提交方立场 | 提交方是原告还是被告（用于在证据目录标题和文书中正确标注） |
| 案件信息 | 案号、审理法院、当事人名称（原告、被告全称） |
| 证据文件 | 需要整理的证据文件路径列表（逐一读取） |

#### 自动判断原告/被告

若用户未明确说明立场，从以下线索自动推断：
- **起诉状/起诉材料** → 提交方可能是原告
- **答辩状/答辩材料** → 提交方可能是被告
- **用户表述** → "我方的证据"、"我们要提交的"等措辞
- **文件名** → 从"原告证据"/"被告证据"等文件名判断

#### 选填信息

| 信息项 | 说明 |
|--------|------|
| 提交人/代理人信息 | 提交人姓名/名称、代理人姓名、联系方式 |
| 特殊说明 | 关于证据的任何补充说明，如保密申请、调取说明等 |

### 第一步：读取证据文件

用 `scripts/read_evidence.py` 逐份读取证据文件：

```bash
python "<skill目录>/scripts/read_evidence.py" "证据文件路径" --output "/tmp/catalog_evidence_N.txt"
```

支持以下格式：

| 格式 | 扩展名 | 读取方式 |
|------|--------|---------|
| PDF | .pdf | pdfplumber / PyPDF2 |
| Word | .docx | python-docx |
| 旧版Word | .doc | olefile |
| 图片 | .jpg/.jpeg/.png/.bmp | AI视觉识别（通过Read工具直接读取） |
| CSV | .csv | 内置 |
| 纯文本 | .txt | 内置（自动检测编码） |
| JSON | .json | 内置 |
| HTML | .html/.htm | beautifulsoup4 |

**图片证据处理**：对于图片格式的证据文件（.jpg/.jpeg/.png/.bmp），脚本会返回 `[IMAGE]` 标记及文件路径，此时应使用 **Read 工具**直接读取图片文件，Claude 将自动识别图片中的文字内容和图像信息。

如果文本超过 50000 字符，用 `--max-chars` 参数调整上限。

全部证据读取完成后，开始整理证据目录。

### 第二步：逐份整理证据信息

**务必同时阅读 `references/evidence_catalog_guide.md` 获取证据目录的格式规范、各类证据的填写要求和常见注意事项。**

对每一份证据，按以下字段逐一整理：

#### 证据目录核心字段

| 字段 | 说明 | 填写要求 |
|------|------|---------|
| **序号** | 证据编号 | 从1开始连续编号，按逻辑顺序排列（时间顺序或证明事项重要程度） |
| **证据名称** | 证据的准确全称 | 应与证据文件标题/内容一致，如"《XX采购合同》"、"2025年3月银行转账凭证" |
| **证据类型** | 法定证据种类 | 书证/物证/视听资料/电子数据/证人证言/鉴定意见/勘验笔录/当事人陈述 |
| **证据来源** | 证据的出处/来源 | 如"XX银行调取"、"XX平台下载"、"原告自行保存"、"XX公证处公证" |
| **页数** | 文件总页数 | 单个文件填实际页数；电子数据可填"1份"或按截图数量计算 |
| **份数** | 提交的份数 | 一般提交1份（原件）/ 2份（复印件），根据法院要求填写 |
| **原件/复印件** | 是否为原件 | "原件"或"复印件"，需如实标注 |
| **证明对象/证明目的** | 该证据用于证明什么事实 | 语言精炼，每项明确指向案件要件事实或争议焦点 |
| **备注** | 补充说明 | 如"另有音频文件存于U盘"、"证据来源于第三方平台"等 |

#### 证据类型的准确归类

| 法定证据类型 | 常见证据举例 | 法律依据 |
|-------------|-------------|---------|
| **书证** | 合同、协议、信函、票据、账册、文件、书面记录等 | 《民事诉讼法》第66条 |
| **物证** | 实物、产品样品、涉案物品照片、现场照片等 | 《民事诉讼法》第66条 |
| **视听资料** | 录音、录像、监控视频、电话录音等 | 《民事诉讼法》第66条 |
| **电子数据** | 微信聊天记录、电子邮件、短信、网页截图、电子支付记录、区块链存证等 | 《证据规定》第14条、第93-94条 |
| **证人证言** | 证人出庭作证书面证言、证人调查笔录等 | 《民事诉讼法》第66条 |
| **鉴定意见** | 司法鉴定报告、价格评估报告、工程造价鉴定等 | 《民事诉讼法》第66条 |
| **勘验笔录** | 现场勘验记录、物证检验记录等 | 《民事诉讼法》第66条 |
| **当事人陈述** | 当事人自书说明、情况说明、事实陈述等 | 《民事诉讼法》第66条 |

#### 证明目的的撰写要求

- 每项证明目的应直接对应案件的争议焦点或要件事实
- 语言精炼、指向明确，单条不超过2句话
- 格式：证明 + 待证事实，如"证明原被告双方于2025年3月1日签订了XX合同，约定……"
- 避免模糊表述如"证明案件事实"、"证明被告违约"等过于笼统的表述
- 一份证据可列多个证明目的（分行列出）

#### 证据排列原则

1. **时间顺序为主**：按证据所反映事实的发生时间先后排列
2. **逻辑层次为辅**：同一事实的多个证据集中排列
3. **重要性补充**：核心证据靠前排列
4. **证明体系完整**：证据之间形成逻辑链条

### 第三步：质量检查

#### 3.1 完整性检查
- [ ] 每份证据文件均已读取并整理
- [ ] 序号连续无遗漏
- [ ] 所有字段均已填写（备注可选）
- [ ] 原件/复印件已如实标注
- [ ] 页数信息准确

#### 3.2 规范性检查
- [ ] 证据类型归类准确，符合法定的8种证据类型
- [ ] 证明目的精炼明确、指向案件要件事实
- [ ] 证据排列逻辑合理
- [ ] 案号格式正确

#### 3.3 一致性检查
- [ ] 证据名称与文件内容一致
- [ ] 总数与实际提交数量一致
- [ ] 份数之和合理
- [ ] 当事人名称前后一致

### 第四步：生成JSON并输出全部文件

证据目录整理完成后，将结果整理为 JSON（格式见下方），依次运行生成脚本。

#### 4.1 准备证据目录JSON

将证据目录保存到 `/tmp/evidence_catalog.json`，格式：

```json
{
  "title": "证据目录——XXX诉XXX案",
  "case_number": "（2026）XX民初XX号",
  "court": "XX人民法院",
  "submitting_party": "原告",
  "party_name": "提交人姓名/公司名称",
  "agent_name": "代理人姓名",
  "submission_date": "2026年05月27日",
  "contact_phone": "138XXXXXXXX",
  "summary": {
    "total_items": 5,
    "total_pages": 23,
    "original_count": 2,
    "copy_count": 3,
    "evidence_types_used": ["书证", "电子数据", "视听资料"],
    "main_facts": [
      "双方存在XX合同关系",
      "被告未按约定履行付款义务",
      "原告已履行合同义务"
    ],
    "notes": "本证据目录所附证据材料共23页，其中原件2份，复印件3份。"
  },
  "evidence_items": [
    {
      "id": 1,
      "evidence_name": "《XX采购合同》",
      "evidence_type": "书证",
      "evidence_source": "原告自行保存",
      "pages": 8,
      "copies": 1,
      "is_original": false,
      "proof_purpose": "证明原被告双方于2025年3月1日签订了XX采购合同，约定被告向原告采购XX设备，总价款为人民币XX元，交货期为2025年6月1日。",
      "remarks": ""
    }
  ],
  "certification": "以上证据材料经本人核对，复印件与原件一致。"
}
```

**JSON 注意事项**：
- 所有中文双引号必须用 `「」` 或 `『』` 代替 `""`
- `submitting_party`: `"原告"` 或 `"被告"`
- `is_original`: `true` = 原件，`false` = 复印件
- 证明目的中的法律文书名称用 `「」` 括起

#### 4.2 确定输出文件夹

从案件名称提取文件夹名，在桌面创建：

```
~/Desktop/<案件名称>证据目录/
```

例如案号为"（2026）粤0106民初1234号"的案件，文件夹名可为"XX诉YY案证据目录"。

#### 4.3 运行生成脚本（顺序运行）

```bash
# 1. 生成 Word 证据目录
python "<skill目录>/scripts/generate_catalog_docx.py" \
  --input "/tmp/evidence_catalog.json" \
  --output "~/Desktop/<案件名称>证据目录/<案件名称>-证据目录.docx"

# 2. 生成 Markdown 报告
python "<skill目录>/scripts/generate_catalog_md.py" \
  --input "/tmp/evidence_catalog.json" \
  --output "~/Desktop/<案件名称>证据目录/<案件名称>-证据目录.md"

# 3. 生成思维导图（.html + .mm）
python "<skill目录>/scripts/generate_mindmap.py" \
  --input "/tmp/evidence_catalog.json" \
  --output-dir "~/Desktop/<案件名称>证据目录/"

# 4. 将 DOCX 转换为 PDF
python "<skill目录>/scripts/convert_to_pdf.py" \
  "~/Desktop/<案件名称>证据目录/<案件名称>-证据目录.docx" \
  --output "~/Desktop/<案件名称>证据目录/<案件名称>-证据目录.pdf"
```

**PDF 转换说明**：
- 脚本按 `docx2pdf (需要Windows上的Word)` → `LibreOffice` → `reportlab` 的优先级尝试
- 如果 Word 已安装，优先使用 `docx2pdf` 获得最佳转换效果
- 如果所有方法都失败，会打印安装提示，此时仅交付 DOCX、MD 和思维导图文件

#### 4.4 输出文件清单

最终桌面文件夹包含：

| 文件 | 说明 |
|------|------|
| `<案件名>-证据目录.docx` | 专业排版的Word证据目录（封面+证据清单表格+提交人声明+签名栏） |
| `<案件名>-证据目录.pdf` | PDF格式的证据目录（由DOCX转换，方便电子送达/打印/法院归档） |
| `<案件名>-证据目录.md` | Markdown格式的证据目录（可在任何编辑器查看） |
| `证据目录思维导图.html` | 交互式思维导图（双击浏览器打开，展示证据体系全貌，双击卡片展开详情） |
| `证据目录思维导图.mm` | FreeMind格式思维导图（可用XMind/FreeMind/Freeplane打开编辑） |

#### 4.5 告知用户

输出完成后告知用户：
- 文件夹路径
- 每个文件的用途
- 建议首先查看 `.html` 思维导图快速了解证据体系，再查看 `.docx` 详细证据目录
- 提醒本文件由AI生成，建议律师复核后使用
- 签名栏和日期栏需手写填写
- 提交法院时需按法院要求准备证据副本份数

## 证据目录范例

以下为标准证据目录的表格格式范例：

| 序号 | 证据名称 | 证据类型 | 证据来源 | 页数 | 份数 | 原件/复印件 | 证明对象/证明目的 | 备注 |
|------|---------|---------|---------|------|------|-----------|----------------|------|
| 1 | 《XX采购合同》 | 书证 | 原告自行保存 | 8 | 1 | 复印件 | 证明原被告双方于2025年3月1日签订了XX采购合同 | |
| 2 | 银行转账凭证 | 书证 | XX银行调取 | 2 | 1 | 复印件 | 证明原告已于2025年3月15日向被告支付首期货款XX元 | 附银行盖章 |
| 3 | 微信聊天记录 | 电子数据 | 原告手机截图 | 5 | 1 | 复印件 | 证明被告承认收到货款并承诺按期交货 | 原始载体为原告手机 |

## 制作原则

### 必须做到

1. **编号连续规范**：证据序号从1开始连续编号，不得跳号
2. **证据名称准确**：与证据文件的实际标题/内容一致
3. **证明目的精炼**：每项证明目的不超过2句话，明确指向待证事实
4. **类型归类准确**：严格按法定8种证据类型归类
5. **页数/份数真实**：如实填写页数和份数，不得虚报
6. **原件/复印件如实标注**：不得将复印件标注为原件
7. **证据排列有序**：按时间或逻辑顺序排列
8. **格式统一规范**：表格排版整齐，字体字号统一
9. **逐份整理、无一遗漏**：每份证据均须单列条目
10. **整体逻辑自洽**：证据之间形成完整证明体系

### 禁止事项

- 不得虚构或伪造证据信息
- 不得将复印件谎标为原件
- 不得遗漏法定证据种类归类
- 不得将证明目的写为"证明案件事实"等笼统表述
- 不得在证据名称中使用简称（除非法院已认可）
- 不得跳号或重复编号
- 不得隐瞒对己方不利的证据（有违诚实信用原则）
