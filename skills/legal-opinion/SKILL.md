# 法律意见书技能

## 这个技能解决什么

意见书最容易出的问题不是写得太短，是**结论没有边界**：

- 材料没看完，写「已审阅全部文件」；
- 把「通常可以」写成「合法有效、不存在风险」；
- 结论超出委托范围，客户拿去给第三方用；
- 引用已废止的旧法，或把会议纪要当法律依据。

本技能强制把「确定」「附条件」「保留」「无法出具」分开写，并把每条依据标上核验状态。

## 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 交易/方案/行为的合法性与风险，需要书面结论 | 只要法条原文或条号 → `legal-statute-lookup` |
| 客户、投委会、监管、对方需要一份可归档的意见 | 只要检索过程、不要结论 → `legal-research` |
| 需要区分确定结论与附条件结论 | 逐条改合同文本 → `legal-contract-review` |
| 需要写明假设、依赖材料、用途限制 | 起诉状、答辩状、上诉状、律师函 → 对应诉讼技能 |
| 内部合规决策留痕 | 已经发生争议、要算请求金额 → `legal-labor-arbitration` |

## 输入

**必需**

1. 委托事项：一句话说清「就什么事、回答什么问题」。
2. 出具对象与用途：给谁看、用于什么（内部决策 / 交易交割 / 投委会 / 监管报送 / 诉讼准备）。
3. 事实与材料：合同、章程、决议、往来邮件、付款凭证等；没有材料的，明确说「基于委托人陈述」。
4. 立场：代表哪一方；中立审查也要写清。
5. 时间要求与是否需要签章版本。

**可选**：已有限制条件、对方意见、交易背景、行业监管要求。

缺失时逐项追问。**尤其不能替客户假设「材料齐全」**——没看到的文件，就是不存在的依据。

## 工作流程

### 第零步：读法律档案

先读 `~/.deepwhale/深鲸法律档案.md`。不存在时，把仓库里的 `templates/法律档案.md` 复制过去，再逐项问用户：角色、立场、执业地域、行文风格、风险偏好、升级链。档案里没填的，不要假设。

档案里的「风险偏好」直接决定措辞：保守型多用「在……前提下」，进取型也要保留底线，不能把保留写成保证。对外出具前必须经过档案里的复核人。

### 第一步：锁定委托事项

把「看看有没有风险」拆成 3–5 个可回答的问题，并写明**本次不回答什么**：

| 客户原话 | 拆出的问题 | 本次不回答 |
|---|---|---|
| 「这个对赌条款有没有效」 | ①条款效力 ②能否实际履行 ③若不能履行如何救济 | 估值是否合理、商业条款是否最优 |

范围写不清，后面很容易跑偏；范围写清了，才能理直气壮地写「超出本次委托范围，未发表意见」。

### 第二步：建立事实基础（三分法）

| 类别 | 写法 | 证据要求 |
|---|---|---|
| 已核实事实 | 「经审阅《XX 合同》第 X 条，……」 | 文件名称 + 条款号/页码 |
| 委托人陈述未核实 | 「根据委托人陈述，……（未经独立核实）」 | 注明来源，不写成定论 |
| 假设 | 「本意见假设……真实、合法、有效」 | 集中列在「假设」一节 |

材料缺失处写【待补：xx】。**不要用「据了解」「一般来说」把缺口抹平。**

### 第三步：法律依据

- 条号到条，司法解释到文号；旧法一律改引《民法典》等现行法；
- 每条标核验状态：已核（条号）/ 待核 / 已被取代；
- 会议纪要、普通案例只作说理参考，单列「参考材料」，不进「法律依据」；
- 拿不准的条号写「相关条文待核」，不猜。

### 第四步：逐项分析

每个问题一节，固定四段：

1. **规则**：适用哪条、构成要件是什么；
2. **涵摄**：本案事实对应哪个要件，哪些事实还不确定；
3. **结论**：落到第 5 步的四档之一；
4. **反向情形**：什么情况下结论会变（这是意见书最值钱的部分）。

### 第五步：结论分级（不得混写）

| 档位 | 什么时候用 | 句式 |
|---|---|---|
| 确定结论 | 事实清楚、规则明确、无实质争议 | 「本所认为，……合法有效/不构成……」 |
| 附条件结论 | 结论依赖未满足的前提 | 「在……完成/取得……的前提下，……；否则……」 |
| 保留结论 | 规则或事实存在实质不确定性 | 「基于现有材料，倾向于……，但因……，本所保留意见」 |
| 无法出具 | 关键事实缺失或事项超出执业范围 | 「现有材料不足以支持结论，本所暂不出具意见」 |

判定口诀：**事实有缺口 → 附条件；规则有争议 → 保留；两者都缺 → 无法出具。** 四档不能为了好看往上抬。

分析里的风险点另用三档标注，与结论四档并用、不互相替代：🔴 必须处理（不满足则结论不成立）/ 🟡 建议处理（可补救，但需写入条件）/ ⚪ 提示。

### 第六步：声明与限制

固定包含：依赖假设、材料范围、用途限制、不更新义务、不构成对第三方的责任、AI 辅助与律师复核。模板见 `references/opinion-structure.md`。

### 第七步：输出与排版

先出 `.md`，律师改完再排版。正式版用 `chinese-doc-formatter` 转 `.docx` / `.pdf`，签章页、日期、出具单位由律师补。

## 输出规范

- 主文件：`法律意见书-<事项>-<YYYYMMDD>.md`
- 依据清单：`依据清单-<事项>.md`（或作为附件），列：依据名称、条号/文号、核验状态、支撑哪个结论
- 需要正式版：`chinese-doc-formatter` → `.docx` / `.pdf`
- 可填写模板：`templates/法律意见书.md`
- 每页页脚或文末固定：

```
本意见基于上述假设与材料范围出具，仅供委托人[用途]使用，不得用于其他目的或向第三方依赖。
AI 辅助生成，需承办律师复核；对外出具须由执业律师签署并承担执业责任。
```

## 质量闸门（交付前自检）

- [ ] 委托事项与「不回答什么」都写清了
- [ ] 事实分「已核实 / 陈述未核实 / 假设」三类，没有混写
- [ ] 每个结论都有依据（条号 / 条款 / 证据编号），无源不写
- [ ] 结论落在四档之一，附条件与保留没有被写成确定结论
- [ ] 没有编造法条条号、案号、金额、日期；缺失处是【待补】
- [ ] 旧法已改引现行法，会议纪要没有被列为法律依据
- [ ] 写了用途限制、不更新义务、依赖假设
- [ ] 带「AI 辅助生成，需承办律师复核」，并提示签章前人工复核
- [ ] 没有「保证」「一定」「必然」「不存在任何风险」

## 输出示例

```markdown
# 法律意见书：XX 项目回购条款的效力与履行

## 一、声明与假设
本意见基于委托人提供的《投资条款清单》及说明出具。假设：①A 公司现行章程合法有效；
②签署方有权代表公司；③未提供的股东会决议、减资文件不存在相反约定。

## 二、事实基础
- 已核实：TS 第 3.2 条约定「未在 3 年内上市，由 A 公司按年化 8% 回购」。
- 委托人陈述未核实：投资款 2000 万元已实缴（未见银行回单）。
- 待补：公司章程、股东会决议、A 公司可分配利润与减资安排。

## 三、法律依据
| 依据 | 条号/文号 | 核验状态 | 支撑 |
|---|---|---|---|
| 民法典 | 第 143 条 | 已核 | 民事法律行为有效要件 |
| 公司法（2023 修订） | 减资程序条文（待核） | 待核 | 回购的履行前提 |
| 《全国法院民商事审判工作会议纪要》（九民纪要） | 第 5 条 | 参考（非法源） | 对赌的说理 |

## 四、分析
### 问题一：条款效力
……（规则—涵摄—结论）

### 问题二：能否实际履行
与目标公司对赌，协议效力与可履行性要分开看；实际回购通常需完成减资程序，
否则可能因违反资本维持原则无法履行。【待补：减资决议与债权人保护程序】

## 五、结论
1. 【附条件】在协议依法签署、不存在第 143 条无效情形的条件下，回购条款本身倾向于有效。
2. 【保留】能否实际履行，取决于 A 公司能否完成减资程序；现有材料不足以判断。
3. 【无法出具】对「3 年内能否上市」不发表意见，超出本次委托范围。

## 六、限制
本意见仅供委托人内部投资决策使用……不构成对第三方责任，不承担更新义务。
AI 辅助生成，需承办律师复核。
```
