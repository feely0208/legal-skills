# 质证意见技能

以中国执业律师视角，针对对方当事人提交的证据材料，围绕证据"三性"（真实性、合法性、关联性）和证明目的，系统性撰写专业质证意见书，最终在桌面生成以案件名命名的文件夹，内含 Word 质证意见书、PDF 文件、Markdown 报告和交互式思维导图。

## 完整工作流程

### 第零步：收集案件信息

在开始质证分析前，向用户确认以下信息（信息充分时直接开始）：

#### 必须确认

| 信息项 | 说明 |
|--------|------|
| 质证人立场 | 质证人是原告还是被告（用于调整策略和文书视角） |
| 案件信息 | 案号、审理法院、当事人名称 |
| 对方证据 | 对方提交的证据文件列表（逐一读取） |

#### 自动判断原被告

若用户未明确说明立场，从以下线索自动推断：
- **起诉状/起诉材料** → 质证人可能是被告（需对原告证据质证）
- **答辩状/答辩材料** → 质证人可能是原告（需对被告证据质证）
- **证据清单标题** → 从"原告证据清单"/"被告证据清单"等标题判断举证方
- **用户表述** → "对方提交的证据"、"我方的证据"等措辞

**策略差异**：

| 维度 | 原告质证（对被告证据） | 被告质证（对原告证据） |
|------|----------------------|----------------------|
| 重心 | 瓦解被告抗辩证据基础 | 削弱原告举证体系 |
| 核心策略 | 证明被告证据不能支持其抗辩 | 证明原告证据不足以支撑诉讼请求 |
| 举证责任利用 | 强调己方已完成举证 | 强调原告举证责任未完成 |
| 常见攻击点 | 被告单方制作证据、无关证据 | 孤证、复制件、未公证电子数据 |

### 第一步：读取证据文件

用 `scripts/read_evidence.py` 逐份读取对方提交的证据文件：

```bash
python "<skill目录>/scripts/read_evidence.py" "证据文件路径" --output "/tmp/evidence_N.txt"
```

支持以下格式：

| 格式 | 扩展名 | 读取方式 |
|------|--------|---------|
| PDF | .pdf | pdfplumber / PyPDF2 |
| Word | .docx | python-docx |
| 旧版Word | .doc | olefile |
| 图片 | .jpg/.jpeg/.png/.bmp | AI视觉识别（通过Read工具直接读取） |
| Excel | .xlsx | openpyxl |
| 旧版Excel | .xls | xlrd |
| CSV | .csv | 内置 |
| 纯文本 | .txt | 内置（自动检测编码） |
| JSON | .json | 内置 |
| HTML | .html/.htm | beautifulsoup4 |

**图片证据处理**：对于图片格式的证据文件（.jpg/.jpeg/.png/.bmp），脚本会返回 `[IMAGE]` 标记及文件路径，此时应使用 **Read 工具**直接读取图片文件，Claude 将自动识别图片中的文字内容和图像信息。

如果文本超过 50000 字符，用 `--max-chars` 参数调整上限。

全部证据读取完成后，开始质证分析。

### 第二步：逐份审查 —— 三性+证明目的

**务必同时阅读 `references/evidence_examination_guide.md` 获取详细的法律依据、各类证据的审查要点和实战策略。**

对每一份证据，按以下四个维度逐一审查：

#### 第一维度：真实性审查

判断证据是否真实存在、未经伪造篡改：

| 审查点 | 核心问题 | 常见质证策略 |
|--------|---------|-------------|
| **形式真实** | 是否原件/原物？复印件/复制品是否与原件相符？ | 非原件不得单独作为定案依据 |
| **内容真实** | 证据内容是否客观存在？有无变造/篡改？ | 签章不一致、涂改痕迹、时间矛盾 |
| **来源真实** | 证据来源是否明确可追溯？ | 来源不明、制作人身份未确认 |
| **完整性** | 证据是否完整，有无断章取义？ | 缺页、剪辑、选择性提供 |
| **电子数据特殊审查** | 是否原始载体？是否经存证/公证？ | 未公证的网页截图可被质疑 |

**重点法条**：
- 《证据规定》第61条：复印件不能单独作为定案依据
- 《证据规定》第92条：私文书证真实性由主张方举证
- 《证据规定》第93条：电子数据真实性审查7要素
- 《证据规定》第94条：电子数据推定真实的5种情形

#### 第二维度：合法性审查

判断证据的取得方式和形式是否符合法律规定：

| 审查点 | 核心问题 | 常见质证策略 |
|--------|---------|-------------|
| **取证主体** | 取证主体是否适格？ | 非当事人/非代理人的私自取证 |
| **取证程序** | 是否严重侵害他人权益或违反禁止性规定？ | 私密空间偷拍偷录、陷阱取证 |
| **证据形式** | 是否符合法定证据种类？ | 鉴定意见缺签名/盖章 |
| **作证资格** | 证人是否有作证能力？ | 利害关系人、无行为能力人 |
| **鉴定资质** | 鉴定机构/鉴定人是否有法定资质？ | 无资质鉴定、超范围鉴定 |

**重点法条**：
- 《民诉法解释》第106条：严重侵害他人权益或违反法律禁止性规定的取证，证据不得采信
- 《证据规定》第36条：鉴定意见形式要件
- 《司法鉴定程序通则》相关条款

#### 第三维度：关联性审查

判断证据与案件待证事实之间是否存在逻辑和法律上的联系：

| 审查点 | 核心问题 | 常见质证策略 |
|--------|---------|-------------|
| **逻辑关联** | 证据与待证事实有无逻辑联系？ | 证据内容与案件无关 |
| **法律关联** | 证据是否指向争议焦点/要件事实？ | 只能证明间接事实 |
| **时间关联** | 证据形成时间是否在争议期间？ | 时间超出争议范围 |
| **主体关联** | 涉及的主体是否与当事人相关？ | 案外人行为与本案无关 |
| **证明方向** | 能否支持举证方的证明目的？ | 证据反而对己方有利 |

**重点法条**：
- 《民诉法解释》第95条：证据与待证事实的关联性审查
- 《民诉法解释》第105条：证据审核认定的综合判断

#### 第四维度：证明目的反驳

针对举证方为每份证据列明的证明目的进行驳斥：

| 反驳策略 | 适用场景 |
|---------|---------|
| 证明目的不成立 | 证据内容与证明目的之间缺乏逻辑联系 |
| 证明力不足 | 单份证据不足以支撑其证明目的 |
| 证据自相矛盾 | 证据内部或与他份证据存在矛盾 |
| 证据反证 | 证据实际上对己方有利，可转化为反证 |
| 孤证不立 | 单一证据无其他证据印证 |

### 第三步：出具审查结论

对每份证据出具明确结论：

| 意见类型 | 表述 | 含义 |
|---------|------|------|
| **无异议** | 对该证据的三性及证明目的均无异议 | 认可该证据 |
| **部分异议** | 对该证据的真实性予以认可，但对其关联性及证明目的有异议 | 部分认可，部分质疑 |
| **完全异议** | 对该证据的三性均不认可，对证明目的不予认可 | 全面否定该证据 |
| **无法确认** | 因证据系复印件/单方制作/来源不明等原因，真实性无法确认 | 存疑，请法院审查 |

### 第四步：整体评价

对对方证据体系进行整体评价：

1. **对方证据体系整体缺陷**：如证据链断裂、关键证据缺失、证据之间相互矛盾
2. **主要攻击点汇总**：提炼所有证据中反复出现的问题
3. **关键缺陷列表**：对对方构成致命打击的证据瑕疵
4. **对法院的建议**：建议法院如何审核认定

### 第五步：生成JSON并输出全部文件

质证分析完成后，将结果整理为 JSON（格式见下方），依次运行生成脚本。

从案件名称提取文件夹名，在桌面创建：


例如案号为"（2026）粤0106民初1234号"的案件，文件夹名可为"XX诉YY案质证意见"。

#### 5.3 运行生成脚本（顺序运行）

```bash
# 1. 生成 Word 质证意见书
python "<skill目录>/scripts/generate_examination_docx.py" \
  --input "/tmp/examination_result.json" \
  --output "~/Desktop/<案件名称>质证意见/<案件名称>-质证意见书.docx"

# 2. 生成 Markdown 报告
python "<skill目录>/scripts/generate_examination_md.py" \
  --input "/tmp/examination_result.json" \
  --output "~/Desktop/<案件名称>质证意见/<案件名称>-质证意见书.md"

# 3. 生成思维导图（.html + .mm）

  --input "/tmp/examination_result.json" \
  --output-dir "~/Desktop/<案件名称>质证意见/"

# 4. 将 DOCX 转换为 PDF
python "<skill目录>/scripts/convert_to_pdf.py" \
  "~/Desktop/<案件名称>质证意见/<案件名称>-质证意见书.docx" \
  --output "~/Desktop/<案件名称>质证意见/<案件名称>-质证意见书.pdf"
```

**PDF 转换说明**：
- 脚本按 `docx2pdf (需要Windows上的Word)` → `LibreOffice` → `reportlab` 的优先级尝试
- 如果 Word 已安装，优先使用 `docx2pdf` 获得最佳转换效果
- 如果所有方法都失败，会打印安装提示，此时仅交付 DOCX、MD 和思维导图文件

最终桌面文件夹包含：

## 质证原则

### 必须做到

1. **法条引用准确**：只引用现行有效法律法规，不确定时以"根据相关法律规定"代替，绝不编造
2. **案例要旨准确**：优先引用最高法公报/指导案例的裁判要旨，无法确认案号时只写裁判观点
3. **三性分别审查**：真实性、合法性、关联性必须分别出具意见，不得笼统表态
4. **证明目的逐一反驳**：对举证方每项证明目的必须回应
5. **意见明确具体**：每项意见必须有具体理由支撑，不得仅写"不认可"而无理由
6. **逐份审查、无一遗漏**：每份证据均须单列条目
7. **立场一致**：全文保持一致的质证人立场视角
8. **每份evidence_item必须包含**：三性verdict+opinion、证明目的反驳、综合意见

### 禁止事项

- 不得编造不存在的法条编号或案号
- 不得仅写"不认可"而不给出理由
- 不得将三性意见笼统合并表述
- 不得使用侮辱性/攻击性语言攻击对方或对方代理人
- 不得不加区分地全面否定所有证据（无异议的应认可）
- 不得遗漏举证方的任何一份证据
- 不得使用"建议法院核实"等推卸审查责任的表述
