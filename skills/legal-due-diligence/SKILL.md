# 尽职调查清单技能

## 这个技能解决什么

尽调最容易出的问题不是「没想到查」，而是**清单长得像目录**：列了 80 项，每项只有一个名词，没人知道向谁要、拿到后看什么、什么算问题。结果资料收了一堆，红旗一个没识别出来。

本技能做三件事：

1. 按交易类型裁剪模块——股权收购查历史包袱，资产收购查资产本身能不能转，投资查成长与对赌，合作查履约能力；
2. 每个检查项写成可执行的四段式：**查什么 / 向谁要 / 看什么 / 红旗信号**；
3. 输出带状态列的清单（已获取 / 待补 / 不适用），让下一轮要资料有依据。

**它不替你查。** 工商、涉诉、被执行、知识产权、资质都可以人工查或接数据源，结果回填到清单。

## 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 股权收购、资产收购前的买方尽调 | 上市公司并购重组的法定披露（规则不同） |
| 增资/参股投资的投前排查 | 财务审计、资产评估（需会计师/评估师出具） |
| 业务合作、代理、联营前的对方履约能力核查 | 单份合同的条款风险审查（用合同审查技能） |
| 卖方/融资方的自查准备（反向使用清单） | 已进入诉讼的举证与证据整理（用证据链技能） |
| 年度供应商/客户准入审查 | 境外主体尽调（法律体系与查询渠道不同） |

## 输入

必需：

- **交易类型**：股权收购 / 资产收购 / 增资投资 / 业务合作（四选一，混合交易分别标注）；
- **标的**：公司名或资产范围；已知的行业、地区；
- **己方角色**：买方 / 投资方 / 卖方 / 合作方（决定清单详略与披露口径）。

可选：

- 已获取资料清单（用于初始状态标记）；
- 交易结构要点（是否承债、是否分立、是否留有原股东、业绩承诺）；
- 关注重点（如「主要担心环保处罚」「核心是那块地」）。

缺失处理：交易类型不明先问清，不要用「通用清单」一把梭；标的不明时先出框架，不编公司名。

## 工作流程

### 第零步：读法律档案

先读 `~/.deepwhale/深鲸法律档案.md`。不存在时，把仓库 `templates/法律档案.md` 复制到该路径，再逐项问用户。重点看：立场（买方/卖方）、风险偏好（保守则红旗阈值低）、执业地域（地方性规定、社保基数、环保要求）。

### 第一步：定交易类型，选模块组合

| 交易类型 | 核心关切 | 必查模块 | 可精简 |
|---|---|---|---|
| 股权收购 | 承继全部历史负债与瑕疵 | 主体、股权出资、重大合同、资产、负债担保、税务、劳动、诉讼处罚、合规 | 业务成长性 |
| 资产收购 | 资产能否干净过户、资质能否延续 | 资产权属、抵押查封、合同可转让性、资质许可、劳动人员安置、税务 | 历史股权沿革 |
| 增资投资 | 估值依据、控制权、退出 | 主体、股权结构、财务与业务、知识产权、核心人员、对赌与优先权历史、诉讼 | 历史沿革细节可减 |
| 业务合作 | 对方履约能力与合规底线 | 主体、资质、履约记录、涉诉与被执行、关联关系、廉洁与制裁 | 股权细节 |

混合交易（如「收购资产+接收团队」）按各模块并集处理，并在清单首页写明拆分。

### 第二步：按模块出清单（四段式）

模块与细项见 `references/尽调清单.md`。每个检查项必须写满四段：

| 列 | 写什么 | 反例 |
|---|---|---|
| 查什么 | 具体文件/事实，可交付物 | 「查合同」 |
| 向谁要 | 目标公司 / 股东 / 登记机关 / 银行 / 客户 / 公开渠道 | 「向对方要」 |
| 看什么 | 3–5 个判断点，带标准 | 「关注风险」 |
| 红旗信号 | 一眼能判的异常，尽量可量化 | 「有风险」 |

示例（股权模块）：

```
查什么：历次增资的出资凭证、验资报告、银行进账单
向谁要：目标公司财务 + 工商档案（登记机关调档）
看什么：①认缴额与实缴额是否一致；②出资时间是否在章程期限内；
        ③是否以非货币出资、评估作价是否合规；④有无抽逃迹象（出资后短期内转出）
红旗信号：认缴 1000 万实缴 0；出资后 30 日内向股东个人账户转出等额资金
```

### 第三步：标状态，区分「未提供」与「不适用」

- **已获取**：资料到手，且已过目（不是「对方说会给」）；
- **待补**：已发清单未收到，或收到但不完整；
- **不适用**：写明理由（如「无境外业务，不涉及数据出境」）。

**不要用「部分获取」糊过去**——拆成两行，已到的那部分标已获取，缺的标待补。状态列是下一轮催资料的依据。

### 第四步：红旗分级与交易影响

对每个红旗做三件事：

1. 分级：🔴 可能构成交易障碍/重大减损；🟡 需在交易文件中处理（陈述保证、赔偿、托管）；⚪ 提示，记录即可；
2. 量化影响：能否用金额/比例表达（补缴社保测算、未决诉讼标的额、担保余额）；
3. 给处置建议：先决条件、价款调整、赔偿条款、escrow、交割前整改、放弃交易。

**只列问题不给处置，等于把活推回给律师。**

### 第五步：出资料需求清单（RFI）

按「先决 — 核心 — 补充」三批发，不要一次甩 200 项：

- 第一批（先决）：主体存续、股权结构、有无重大诉讼/被执行、核心资质是否有效——决定要不要继续；
- 第二批（核心）：合同、资产、负债、税务、劳动；
- 第三批（补充）：历史沿革细节、非重大关联交易。

每项写：编号、资料名称、期间（如 2022-01-01 至今）、形式（原件/盖章复印件/电子版）、提供方、截止日、用途。给对方的版本删去「红旗信号」列。

### 第六步：输出与复核

按 `## 输出规范` 落盘。清单是工作底稿：每轮更新状态，保留版本日期。正式报告（尽调报告/风险提示函）不在本技能范围，需另行起草。

## 输出规范

默认输出到项目目录 `尽调/<标的简称>/`：

| 文件 | 内容 | 格式 |
|---|---|---|
| `尽调清单.md` | 按模块分组，四段式 + 状态 + 分级 | .md |
| `尽调清单.csv` | 同上，UTF-8 BOM，可导入 Excel 跟踪 | .csv |
| `资料需求清单.md` | 三批 RFI，可直接发对方 | .md |
| `红旗汇总.md` | 按🔴🟡⚪排序，含影响与处置建议 | .md |
| `进度看板.md` | 模块完成度、待补项数、阻塞项 | .md |

给对方的 RFI 不含内部判断列；内部版保留。需要正式排版用 `chinese-doc-formatter` 转 .docx/.pdf。

## 质量闸门（交付前自检）

- [ ] 交易类型已确认，模块组合与之匹配，没有直接套通用清单
- [ ] 每个检查项都写满「查什么/向谁要/看什么/红旗信号」四段，没有只有名词的条目
- [ ] 状态列只有已获取/待补/不适用三种，且不适用写了理由
- [ ] 每个🔴红旗都有量化影响和处置建议
- [ ] 没有编造公司名、金额、处罚记录、案号；未知项写【待补：xx】
- [ ] 未声称已联网查询工商/涉诉；查询渠道写成「人工查询/自接数据源」
- [ ] 引用的公司法、劳动法条号与现行文本一致，拿不准标「相关条文待核」
- [ ] 文末有「AI 辅助生成，需承办律师复核」

## 输出示例

```markdown
## 模块三 重大合同（股权收购）

| 编号 | 查什么 | 向谁要 | 看什么 | 红旗信号 | 状态 |
|---|---|---|---|---|---|
| C-01 | 前五大客户合同及补充协议 | 目标公司商务 | ①是否独家/排他；②有无最低采购承诺；③控制权变更条款；④账期与罚则 | 合同约定「控制权变更需对方同意，否则可解约」 | 待补 |
| C-02 | 全部对外担保合同 | 目标公司财务 + 征信报告 | ①担保余额；②是否互保；③有无反担保 | 为股东关联方担保且未披露 | 已获取 |

🔴 C-02：为控股股东 800 万元借款提供连带保证，主债务 2026-12 到期。
影响：承债 800 万元，占交易对价 16%。
处置：列为交割先决条件，要求解除担保或等额扣减价款。
```
