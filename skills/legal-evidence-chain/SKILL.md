# 证据链时间线技能

## 这个技能解决什么

当事人递来一个网盘文件夹：几十张聊天截图、一份银行流水、两份合同、三段录音。真正花时间的不是读，是**把材料变成能支撑构成要件的东西**：

- 同一件事有五份材料，时间对不上，谁先谁后说不清；
- 每份材料都「有用」，但对应哪个待证事实、能证到什么程度，没人写下来；
- 缺口藏在中间：合同签了、货发了，但没交付凭证；
- 代理被告时，同一份材料的意义完全反过来（原告的「催告」是被告的「时效中断」）。

本技能产出一张可核对的时间线表、一张事实—证据映射表、一份按优先级排序的缺口清单。**它不判断胜负，只把「现有材料能证明什么、还差什么」写清楚。**

## 适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 起诉/应诉前梳理全部在手材料 | 判断证据是否会被法院采信（需结合庭审质证） |
| 民间借贷、买卖、服务合同、租赁、劳动、离婚财产等民商事案件 | 刑事案件阅卷与证据合法性审查（需专门规则） |
| 客户只给零散截图/流水，需要先搭骨架 | 单份合同条款风险审查（用合同审查技能） |
| 已有一版时间线，需要找矛盾和缺口 | 法条与案号真伪核验（用 legal-cite-check） |
| 代理一方，需要确定补强顺序 | 出具正式《证据目录》《质证意见》（用对应文书技能） |

## 输入

必需：

- **立场**：代理原告 / 代理被告 / 中立审查（决定重要性标记，见第五步）；
- **案由或争议类型**：借贷、买卖、租赁、劳动、离婚后财产等（决定构成要件与举证责任）；
- **材料**：文本、表格、聊天导出、录音转写稿。图片和录音请先本地 OCR/转写，转写稿要带时间戳。

可选：

- 待证事实清单（客户或律师已列）；
- 对方已提交的证据（用于做矛盾比对）；
- 关键时间节点（立案、催告、解除通知）。

缺失处理：立场不明先问，不要默认原告；材料没有形成时间就标【待补：形成时间】，不要按文件修改时间倒推。

## 工作流程

### 第零步：读法律档案

先读 `~/.deepwhale/深鲸法律档案.md`。不存在时，把仓库 `templates/法律档案.md` 复制到该路径，再逐项问：角色、立场、执业地域、行文风格、风险偏好、升级链。档案里没填的不要假设。

### 第一步：定框架——案由、构成要件、举证责任

1. 写出案由与请求权基础（如「民间借贷返还本金」→ 借贷合意 + 款项交付）；
2. 拆成 2–5 个**待证事实**，编号 F-01、F-02……每个事实对应一个构成要件，不写「被告违约」这种结论式事实；
3. 标举证责任：一般「谁主张、谁举证」（《民事诉讼法》第六十七条）；举证责任倒置或转移的情形单独标（如劳动争议中用人单位掌握管理的证据、民间借贷中被告抗辩转账系偿还旧债后的再举证）。
4. 立场决定框架重心：代理原告要补全要件；代理被告优先找**权利未发生、已消灭、时效届满、要件缺失**。

### 第二步：材料登记与四要素抽取

每份材料给唯一编号 **E-01** 起，逐份记录（模板见 `templates/材料登记表.csv`）：

| 字段 | 要求 |
|---|---|
| 证据编号 | E-01，后续所有引用只用编号 |
| 材料名称/形式 | 微信聊天记录、银行流水、借条、合同、录音转写、快递单 |
| 时间 | 材料形成时间；聊天记录取消息时间，流水取交易时间，合同取签署时间 |
| 主体 | 谁对谁：账号/户名/手机号/身份证号后四位，写清如何与当事人对应 |
| 金额 | 币种、数额、方向（谁付谁）、是否含利息/手续费 |
| 行为 | 一句话动词短语：「承诺 3 月底还款」「交付 200 箱货」「单方停止供货」 |
| 原件状态 | 原件/原始载体/复印件/截图/转写稿 |
| 取得方式 | 自己留存/对方提供/公证/律师调查令/平台调取（合法性初筛） |
| 证明目的 | 指向哪个 F 编号，或「背景事实」 |

规则：

- **一份材料多个行为就拆多行**，不要一句话塞五个动作；
- 时间只到日的写日期，聊天记录写到分钟；时区不明不影响，但跨时区交易要注明；
- 金额不明确写【待补：金额】，不估算；
- 无法对应任何 F 的进「背景材料」区，不删——被告可能用得上。

### 第三步：排时间线

按时间升序排；同一天按「签约 → 履行 → 催告 → 拒绝」的业务逻辑排，不按文件名字母排。

- 时间不明的单独放「时间待定」区，**不要硬塞到某个日期**；
- 关键节点加粗：合同成立、款项交付、履行期届满、首次催告、明确拒绝、起诉/仲裁；
- 每条时间线记录都带 E 编号，没有 E 编号的「事实」是客户口述，标 `[口述]` 并单列，不能混进证据行。

### 第四步：事实—证据映射

对每个 F 编号做三件事：

1. 列支持证据（E 编号）与反对证据；
2. 判定状态：
   - **已证**：有原始载体，且能同时锁定主体、金额/行为、时间，无相反证据；
   - **待补**：只有间接证据、只有截图无原始载体、或主体无法对应；
   - **矛盾**：两份以上材料在时间/金额/主体/行为上冲突，且无法用合理解释消除。
3. 写「还差什么」：一句话写清缺的那一环（如「缺交付签收单」「缺 3 月 5 日之后的聊天记录」）。

映射表格式见 `references/证据链方法.md` 第三节。

### 第五步：按立场重排重要性

**同一份证据，原告和被告的标记不同。**这是本技能最容易做错的地方，必须显式写出来：

| 情形 | 代理原告 | 代理被告 |
|---|---|---|
| 对方在聊天中承认欠款 | 🔴 核心，必须固定原始载体 | 🔴 先看是否断章取义、有无后续抵销约定 |
| 只有转账无借条 | 🔴 缺口，需补借贷合意 | 🟡 可用于抗辩「系还款/投资/赠与」 |
| 原告长时间未催告 | 🟡 需解释，准备时效中断证据 | 🔴 主打诉讼时效抗辩（《民法典》第一百八十八条三年） |
| 己方发出的解除通知 | 🔴 证明解除时点与理由 | 🔴 审查解除理由是否成立、程序是否合法 |
| 证人系己方近亲属 | 🟡 证明力弱，需补书证 | 🔴 攻击利害关系（《民事诉讼证据规定》第九十条） |

输出时在时间线表和缺口清单里都保留「原告视角 / 被告视角」两列，或明确声明本次只做哪一方。

### 第六步：证明力与合法性初筛

对每份关键证据过快检（细则见 `references/证据链方法.md` 第四、五节）：

- **真实性**：原件/原始载体是否在；截图能否与原始手机对应；电子数据是否有完整上下文；
- **合法性**：取得方式是否严重侵害他人权益、违反禁止性规定或严重违背公序良俗（《民诉法解释》第一百零六条）；偷录的私密场所录音、擅自侵入他人账号获取的聊天记录要标🔴；
- **关联性**：材料上的主体能否与当事人对应（微信昵称 ≠ 本人，需实名信息、绑定手机号、转账记录、头像朋友圈等佐证）；
- **孤证**：单一证据且对方不认可，按《民事诉讼证据规定》第九十条标🟡，不能标「已证」。

### 第七步：出缺口清单与补强动作

每条缺口写五件事，缺一不可：

1. 缺口描述（缺哪一环）；
2. 影响哪个 F、当前状态；
3. **向谁要**：己方当事人 / 对方 / 第三方（银行、快递、平台、不动产登记中心、社保局、公安）；
4. **怎么取得**：自行调取 / 申请法院调查令 / 申请法院调取 / 公证保全 / 律师持令查询；
5. 可行性与时限：现在还能不能拿到、有没有超过保存期限、是否需要在举证期限内申请。

按 🔴 必须补（不补要件不成立）/ 🟡 建议补（影响数额或证明力）/ ⚪ 提示 三档排序。**不要给「建议进一步收集证据」这种空话。**

### 第八步：输出与复核

按 `## 输出规范` 落盘，最后跑一遍质量闸门。涉及提交法院的证据目录，提示由承办律师复核后再定稿。

## 输出规范

默认输出到案件工作目录下 `证据链/`：

| 文件 | 内容 | 格式 |
|---|---|---|
| `时间线.md` | 按时间排序的主表 + 时间待定区 + 关键节点 | .md |
| `时间线.csv` | 同上，UTF-8 BOM，Excel 可开（列定义见 templates） | .csv |
| `事实证据映射.md` | F-01…逐项：要件、支持证据、反对证据、状态、还差什么 | .md |
| `证据缺口清单.md` | 按🔴🟡⚪排序，每条五要素 | .md |
| `材料登记表.csv` | 第二步的完整登记 | .csv |

命名不带客户真实姓名，用「案由-代号」，避免文件名泄露。需要给客户或法院的正式版本，用 `chinese-doc-formatter` 转 .docx/.pdf。正式提交用的证据目录用文书类技能生成，本技能的输出是它的上游素材。

## 质量闸门（交付前自检）

- [ ] 每条时间线记录都有 E 编号或 `[口述]` 标记，没有「无源事实」
- [ ] 每份证据的四要素齐全，缺失处是【待补：xx】而不是空白或猜测
- [ ] 每个 F 都有状态（已证/待补/矛盾），没有「基本可以认定」这类模糊结论
- [ ] 已显式写明本次立场；原告/被告标记没有被混用
- [ ] 矛盾点写清了冲突在哪两个字段，不是只写「存在矛盾」
- [ ] 缺口清单每条都有「向谁要 + 怎么取得」，没有空泛建议
- [ ] 没有编造金额、日期、账号、条号；不确定的条号写「相关条文待核」
- [ ] 未上传任何材料、未联网；图片/录音均为本地转写
- [ ] 文末有「AI 辅助生成，需承办律师复核」

## 输出示例

```markdown
## 时间线（节选）

| 日期 | 主体 | 行为 | 金额 | 证据 | 备注 |
|---|---|---|---|---|---|
| 2024-03-01 | 张某→李某 | 转账，附言「借款」 | 200,000 | E-01 银行流水 | 原始载体在手 |
| 2024-03-01 | 李某→张某 | 微信「收到了，年底还」 | — | E-02 聊天记录 | 账号主体待证 |
| 2024-12-31 | 张某→李某 | 微信催告 | — | E-03 | 时效中断 |
| 时间待定 | 李某 | 口头承诺延期 | — | [口述] | 无证据，不计入 |

## F-01 借贷合意｜状态：待补 🟡

- 支持：E-02（承认收款并承诺还款）、E-03（催告未否认）
- 反对：无
- 还差什么：E-02 只有截图，缺原始载体与微信号实名对应；需当庭出示手机或做公证。
```


## 脱敏：用现成 App，不在本技能里做

卷宗里的姓名、身份证、手机号、案号等，**先用深鲸「文书脱敏」App（鸿蒙，端侧处理、未申请联网权限）处理**，导出脱敏件后再交给本技能：

- App 说明页：https://www.deepwhale.org.cn/desensitize.html
- 为什么不做成技能：脱敏的难点是 OCR、版面还原与端侧性能，做成 Agent 技能效果差；现成 App 更稳，也不把当事人信息带进任何模型。

本技能只处理**已经脱敏的文本**，不接收原始证件照片，也不做图像识别。
